# 4. Agent 行为血缘

## 核心问题

传统数据血缘回答“数据从哪里来”，行为血缘还要回答“Agent 做了什么、为什么这么做”。真实事故中，一笔错误退款因没有保存当时的数据快照、Prompt 版本和模型版本，团队查了一天仍无法复现，只能赔偿。

行为血缘的目标是把动作及其全部依赖绑定成可 100% 重放的现场，把 AI 的每次决策作为顶层资产纳入血缘图。

## 三层 Trace

| 层次 | 覆盖范围 | 工具 / 组合 | 回答的问题 | 粒度 |
| :--- | :--- | :--- | :--- | :--- |
| Data Lineage | 表 / 文件 → 上游 | OpenLineage | 这份数据怎么来的 | 表级 / 字段级 |
| Call Trace | 请求 → 服务 → 服务 | OpenTelemetry | 请求耗时在哪里 | 服务级 / span 级 |
| Action Lineage | 动作 → 决策依据全链路 | OL + OTel + audit | 为什么 AI 这么做 | 动作级 + 依据 |

Action Lineage 不是另建系统，而是用同一个 `trace_id` 串起 OpenLineage、OpenTelemetry 和 append-only audit。

## 动作的五元绑定

| 维度 | 绑定内容 | 目的 | 来源 |
| :--- | :--- | :--- | :--- |
| Data Snapshot | iceberg_snapshot_id | 锁定数据快照 | Week 4 Iceberg V3 time travel |
| Evidence Chunks | chunk_id + doc_version | 锁定具体引用证据 | Week 7 evidence_anchor |
| Prompt Version | prompt_release_id | 锁定 LLM 行为约束 | Week 8 Prompt as Code |
| Tool / Skill Version | tool_v + skill_pack_release | 锁定动作执行约束 | Week 9 SKILL.md |
| Model Version | claude-sonnet-4-6 | 锁定推理模型 | Week 8 release manifest |

五类上下文缺一项，复盘就多一个说不清，动作也不具备完整可追责性。

## Trace Event 应记录什么

讲义中的动作完成事件由以下信息组成：

- **事件身份**：`event_type=agent.action.completed`、trace_id、session_id。
- **动作 action**：动作类型、tool_name、tool_version、args_hash、result_code，说明“做了什么”。
- **依据 reasoning**：user_query、evidences 中的 chunk_id 和 doc_version、data_snapshots，说明“为什么”。
- **绑定 bindings**：release_id、prompt_release_id、model_version、skill_pack_release；工具版本在 action 中共同完成五元绑定。
- **审批 approval**：approver，把 HITL 审计接入责任链。

示例事件使用了这些具体版本和标识：`trace-20260518-001`、工具 `ticket_update` 版本 `1.4.0`、文档版本 `v3.7.2`、数据快照 `snap_2026_05_18_093200`、发布 `rag-v2026.05.18-001`、Prompt `v3.2.1`、模型 `claude-sonnet-4-6`、Skill 包 `1.4.0`。这些是讲义示例值，不应被理解为通用固定配置。

## 接入既有治理栈

`Agent 生成 trace_id → OpenLineage 记录数据 / 模型血缘 → OpenTelemetry 记录调用 span → Audit Log 记录合规事件 → Unified View 按 trace_id 关联`

- OpenLineage 的 inputs 包含决策依赖的数据快照和 RAG 切片。
- outputs 指向动作修改的资产，从而可反查哪些 Agent 动作改过该资产。
- session_id 作为 parent run，把一次会话中的多个动作组成血缘子图。
- DataHub、Marquez 或 OpenMetadata 可将 Agent 动作和数据资产放在统一图中查看。

## Action Replay

| 场景 | 需要什么 | 没有血缘的代价 |
| :--- | :--- | :--- |
| 客户投诉复盘 | 重放现场和决策依据 | 人工查日志数小时 / 数天 |
| Bug 回归 | 修改后重跑历史 case | 无法对比，只能猜测 |
| 合规审计 | 解释决策为何符合监管 | 审查直接失败 |
| 模型对比 | Claude Sonnet 4.6 与 Claude Opus 4.8 严格 A/B | 无法严格对比 |

Action Replay 的验收问题是：客户投诉上周三退款额错误时，能否在 5 分钟内重放当时现场。

## Recap

- 数据血缘、调用链和动作血缘各司其职，以同一 trace_id 关联。
- 五元绑定是动作可重现性的硬门槛。
- 行为事件同时记录“做了什么”“为什么”和“谁批准”。
- 血缘的最终价值是可靠重放，而不只是查询日志。
