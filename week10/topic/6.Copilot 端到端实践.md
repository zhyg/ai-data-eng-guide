# 6.Copilot 端到端实践

## 核心目标

本节把前五课的工具契约、路由与回退、HITL、行为血缘和端到端闭环组装为一套“实现与验收”清单，让知识问答系统升级为能执行生产动作、同时受控、可审计、可恢复的 Copilot。

## 组装目标与整体链路

`用户 / session_id → Router → 契约化工具集 → 主链路或五级 fallback → 风险矩阵 → 异步 HITL → 执行结果 → Action Lineage → 统一响应与监控`

其中 RAG 也作为 `knowledge_search` 工具参与统一路由，而不是保留另一套特殊调用体系。

## 关键模块及职责

| 模块 | 主要职责 | 与其他模块的关系 |
| :--- | :--- | :--- |
| Tool Contracts | 约束输入、输出、错误码、角色、幂等和审计字段 | 为 Registry、执行器、审计提供统一事实来源 |
| Tool Registry / Router | 先按规则或意图缩小工具集，再由 LLM 做窄决策 | 高风险、高确定性任务转显式 Workflow |
| Fallback Chain | 固化 Primary、Retry、Fallback、HITL、Graceful 五级路径 | 每级独立超时、结果和 audit |
| HITL Workflow | 按风险矩阵移交决策权，保存 checkpoint 并异步恢复 | 与权限校验、审批 SLA、Action Lineage 相连 |
| Action Lineage | 关联动作、依据、版本、审批和结果 | 用 trace_id 串联 OpenLineage、OpenTelemetry、audit |
| SLO / Health | 持续检查证据覆盖、工具成功、审批响应和幻觉 | 触发告警、回归和后续治理 |

## 契约与数据模型检查

### 工具契约最小字段

- name、description；description 需要同时说明适用和 “NOT for” 边界。
- input_schema 与 output_schema；使用 required、enum、format、长度 / 数值范围，并拒绝额外字段。
- allowed_roles 与 actor 校验。
- 幂等策略；写类动作要求 idempotency_key，查询可标记 natural。
- failure_codes 与预定义 fallback。
- audit_fields，至少包括 actor、args_hash、result_code、trace_id。

### 审批对象与状态

- approval_request：request_id、risk_category、approval_layer、关键上下文和 SLA。
- checkpoint：request_id 对应的 agent_state、pending_action、expires_at。
- 决策记录：approver、decision、reason，以及 requested / notified / decided / executed 各时点事件。
- 审计存储应为 append-only，拒绝理由必填。

### 行为血缘事件

- 身份：event_type、trace_id、session_id。
- 动作：type、tool_name、tool_version、args_hash、result_code。
- 依据：user_query、EvidenceAnchor 中的 chunk_id / doc_version、数据快照。
- 五元绑定：Data Snapshot、Evidence Chunks、Prompt Version、Tool / Skill Version、Model Version。
- 审批：approver、decision、reason，并与动作结果在同一 trace 下关联。

## 路由、失败与审批路径

### 正常知识问答

`用户问题 → Router 选择 knowledge_search → 返回至少 1 条 EvidenceAnchor → 生成带证据答案 → 写入五元绑定和 trace`

验收重点：查询边界正确、evidences ≥ 1、引用准确、Evidence Coverage = 100%。

### 工具失败

`实时 API → 1500 ms 超时 → 最多 3 次指数退避重试 → 最多 300 秒缓存并标 stale → 异步通知人工 → 固定 graceful 响应`

验收重点：每层独立超时和审计；能从 `fallback_level` 与主错误码判断实际路径；缓存结果必须明确告知 stale，不能冒充实时数据。

### 高风险动作

`风险规则命中 → 生成 approval_request → 保存 checkpoint → 异步通知 → Agent 释放资源 → callback 决策 → 校验审批角色 → resume → 执行 / 拒绝 / 升级 → 完整审计`

财务、不可逆和合规动作强制进入 HITL；退款 > 1000 元和一小时 5 次重试分别触发主管与安全团队审批。不得让 LLM 自行决定是否绕过审批。

## 契约测试与健康检查

### 契约层

- 缺少 required 字段、出现未知字段、enum 越界、format 错误时均拒绝执行。
- 未授权角色返回结构化 `PERMISSION_DENIED`，并产生审计事件。
- 同一 idempotency_key 与同一参数重复请求只执行一次；并发请求不能双穿透。
- 已声明失败码都能映射到明确 retry、fallback 或用户响应。
- `knowledge_search` 的 query 最长 500、top_k 为 1–10、evidences 至少 1 条。

### HITL 层

- 5000 元退款先进入 awaiting_approval，风险类别为 financial，不能直接执行。
- 审批等待期间 Agent 不占用会话执行资源，checkpoint 可持久恢复。
- SLA 到期按预设路径升级、拒绝或转人工，不允许事务挂死。
- 批准、拒绝和角色不匹配均可验证；发起、通知、决策、执行事件完整且不可篡改。

### 血缘与回放层

- 同一 trace_id 能关联路由、工具调用、fallback、审批、OpenLineage、OTel span 和 audit。
- 五元绑定缺一项即判定动作不可发布。
- 历史投诉场景可恢复当时的数据快照、证据、Prompt、工具 / Skill 和模型版本。
- 复现后能对比动作参数哈希、结果码和审批责任链。

### 端到端路径

| 路径 | 场景 | 必验结果 |
| :--- | :--- | :--- |
| Happy | 如何重置密码 | evidences ≥ 1，引用准确，五元绑定完整 |
| Fallback | 工单 API 超时 | cache / graceful 可达，fallback_level 有审计 |
| HITL | 退款 5000 元 | checkpoint、异步审批、三段以上 audit chain、恢复执行 |
| Composite | 查 KB 后改工单 | 单 trace_id 关联多个动作 |
| Replay | 历史投诉 | 能重放当时决策依据 |

## 上线健康门槛

| 指标 | 目标 |
| :--- | :--- |
| Resolution Rate | > 65% |
| Evidence Coverage | = 100% |
| Tool Success Rate | > 98% |
| HITL SLA：15 分钟内响应率 | > 95% |
| Hallucination Rate（抽样） | < 2% |

五项指标都需要面板和阈值告警；其中证据覆盖率没有容忍区间。

## 最终验收清单

- 工具的 Schema、幂等、权限、审计四证齐全。
- 路由按确定性与风险分级，不向 LLM 暴露不必要的自由度。
- 五级 fallback 每一级可测试、可定位、可审计。
- HITL 异步、可超时、可降级、可恢复，触发规则由代码强制。
- 每个动作完成五元绑定，并可通过统一 trace 重放。
- Happy、Fallback、HITL 三条必跑路径及 Composite、Replay 两条进阶路径上线前全部通过。
- SLO 持续监控；上线后进入评测、可观测、治理与成本优化阶段。
