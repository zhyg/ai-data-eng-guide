# 5. 端到端 Copilot 闭环

## 核心目标

Demo 跑通不等于 Copilot 上线。讲义的判断是：Demo 三天可以完成，但真实上线离不开前 10 周的工程承诺。端到端闭环要让系统能办事、办错可追责、上游变更不崩、合规审查可通过。

## 缺少哪层，会发生什么

| 缺失能力 | 会缺什么 | 后果 |
| :--- | :--- | :--- |
| Week 2 契约 | Agent 拿到的数据不可信 | 答案地基不稳 |
| Week 6/7 资产化 + 多模态 | 数据不稳定、无法回答复杂问题 | 深问即暴露问题 |
| Week 8 RAG 服务化 | 答案没有证据 | 无法通过合规第一关 |
| Week 9 Skill 标准 | 没有可治理的工艺 | 无从持续优化 |
| Week 10 契约 + HITL + 血缘 | 动作没有边界 | 一执行就可能造成事故 |

## 端到端架构

`User / session_id → Router（Intent + Tool，LLM 窄决策）→ Tools（RAG / Query / Update）→ HITL（高风险异步审批 + audit）→ Trace（五元绑定 + action lineage）`

Agent 不是黑盒，而是一组有序工程对象。每一段都必须可观测、可审计、可降级，并能清楚回答其职责和故障处置方式。

## 上线演示：3 类必跑 + 2 类进阶

| 路径 | 场景 | 验证什么 | 关键检查点 |
| :--- | :--- | :--- | :--- |
| Happy | “如何重置密码” | RAG → 答案 + 五元绑定 | evidences ≥ 1，引用准确 |
| Fallback | 工单 API 超时 | fallback → cache → graceful | fallback_level audit |
| HITL | 退款 5000 元 | Pre-Confirm → 异步审 → 执行 | approval audit + checkpoint |
| Composite | 查 KB + 改工单 | workflow 编排 + trace 关联 | 单 trace_id 关联多动作 |
| Replay | 上周投诉案例 | Action Replay 重放现场 | 复现当时决策 |

这五类路径都应成为自动化测试和演示脚本，上线前 100% 通过并在上线后定期回归。只验证 happy path 仍是 Demo 级系统。

### HITL 路径的闭环验收

讲义用 5000 元退款说明发布前检查：

1. 请求到达后应返回 awaiting_approval，而不是直接执行；风险类别为 financial。
2. 审批人批准并填写理由后，Agent 从 checkpoint 自动恢复。
3. 最终动作 result_code 为 SUCCESS。
4. audit chain 至少有 3 段，覆盖发起、审批和执行。
5. 同时验证 release、risk、audit、approver、bindings 和 trace 等工程对象。

异步客户端可以轮询完成状态，但 Agent 自身不能在等待时阻塞。

## 五个核心 SLO

| 指标 | 含义 | 目标值 | 违反的代价 |
| :--- | :--- | :--- | :--- |
| Resolution Rate | 一次解决率 | > 65% | 工单成本上升 / NPS 下降 |
| Evidence Coverage | 答案带证据率 | = 100% | 合规失败 / 信任流失 |
| Tool Success Rate | 工具调用成功率 | > 98% | 用户体验断崖 |
| HITL SLA | 审批 15 分钟内响应率 | > 95% | 事务挂死 |
| Hallucination Rate | 幻觉率（抽样） | < 2% | 风险 + 合规问题 |

五项都需要专属监控面板和阈值告警。Evidence Coverage 必须是 100%，不能以“大概覆盖”代替。

## Industry Signals

| 框架 / 法规 | 要求 / 能力 | 工程含义 |
| :--- | :--- | :--- |
| OpenAI Agents SDK（2025.3） | 工具路由、fallback、tracing 为一等能力 | 生产部署事实标准 |
| LangGraph for Production | stateful workflow + interrupt + durable | 生产 Agent 编排框架 |
| Anthropic：Workflow over Agent | Workflow + 受控工具 + HITL | 生产环境几乎不存在全自由 Agent |
| EU AI Act + 中国生成式 AI 备案 | 强制审计、HITL、行为追溯 | 监管推动 Copilot 工程化 |

讲义强调 Copilot 的上线准入条件是“受控 + 可解释 + 合规审计”，并提到 EU AI Act 罚则可达营收 3%。

## Recap

- 完整能力栈是 `Tool 契约 → Route 路由与降级 → HITL 人工护栏 → Trace 行为血缘 → Loop 端到端闭环`。
- 上线验收必须覆盖成功、失败和审批路径，并加入组合与重放测试。
- 五项 SLO 把“是否真正上线”变成可量化约束。
- Week 10 是上线里程碑，后续仍需持续评测、观测、治理和成本优化。
