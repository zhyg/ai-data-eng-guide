# 导学 05：一条成功演示，为什么还不算 Copilot 上线？

## 一句话理解

端到端 Copilot 闭环把请求路由、工具执行、失败回退、人工审批、行为追踪、交付和监控连成可治理流程。

## 用生活打比方

继续我们的物流配送中心。客户下单后，调度台识别任务并选择通道，仓库按作业单执行，高风险操作等待审批，每次处理都进入追踪记录。包裹交付后，系统还要监控查询是否有依据、操作是否成功、审批是否及时以及异常是否得到处理。正常配送、系统故障、审批任务、组合操作和历史回放都跑通，配送中心才具备稳定营业条件。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **端到端闭环（End-to-end Loop）** | 从用户请求到执行、交付和监控都能接续，异常也有明确去处。 |
| **受控路由（Controlled Routing）** | 让模型只处理窄范围判断，其余选择由规则和流程约束。 |
| **组合路径（Composite Path）** | 一个请求连续使用知识查询和业务操作，并用同一追踪标识关联。 |
| **回放路径（Replay Path）** | 用历史现场检查系统能否还原当时的依据与动作。 |
| **服务目标（Service Level Objective）** | 团队为证据覆盖、工具成功、审批响应和回答质量设定的运行目标。 |
| **持续监控（Continuous Monitoring）** | 上线后持续采集指标并告警，发现闭环中哪个环节偏离目标。 |

## 避坑提醒

- **以为正常问答跑通就是可以上线**：还要验证工具故障、人工审批、组合动作和历史回放。
- **以为 Agent 就是一个黑盒程序**：路由、工具、人审和追踪都应有清楚职责与故障处理方式。
- **以为有审计日志就是形成闭环**：还要能关联请求、动作、依据、审批、交付结果和监控指标。
- **以为发布验收就是一次检查**：关键路径要进入自动化测试，并在上线后持续回归和监控。

## 一句话总结

> **Copilot 达到上线条件，要同时通过成功、失败、审批、组合与回放路径的验收。**
