# 导学 05：一条成功演示，为什么还不算 Copilot 上线？

## 一句话理解

端到端闭环是把前面讲的请求路由、工具执行、失败回退、人工审批、行为追踪全部串起来，加上交付和监控，形成一个可治理的完整流程。

## 用生活打比方

继续我们的物流配送中心。客户下单后，调度台识别任务选通道，仓库按作业单执行，高风险操作暂停等审批，每步处理都进追踪记录。包裹交付之后事情还没完，系统要持续监控：查询回答有没有依据，操作有没有成功，审批响应快不快，异常有没有被处理。正常配送、系统故障、审批流程、组合操作、历史回放这些场景都跑通了，配送中心才算具备稳定营业的条件。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **端到端闭环（End-to-end Loop）** | 从用户请求到执行、交付、监控都能接得上，异常也有明确的去处。 |
| **受控路由（Controlled Routing）** | 模型只处理窄范围的判断，其余选择由规则和流程兜住。 |
| **组合路径（Composite Path）** | 一个请求先查知识再做业务操作，用同一个追踪标识把两段关联起来。 |
| **回放路径（Replay Path）** | 拿历史现场检查系统能不能还原当时的依据和动作。 |
| **服务目标（Service Level Objective）** | 团队给证据覆盖率、工具成功率、审批响应时间、回答质量定的运营指标。 |
| **持续监控（Continuous Monitoring）** | 上线后不断采集指标、设告警，发现闭环里哪个环节开始跑偏。 |

## 避坑提醒

- **以为正常问答跑通就是可以上线**：工具故障、人工审批、组合动作、历史回放这些路径都得验过。
- **以为 Agent 就是一个黑盒程序**：路由、工具、人审、追踪各有职责，每一块都该有清楚的故障处理方式。
- **以为有审计日志就是形成闭环**：还得能把请求、动作、依据、审批、交付结果和监控指标关联到一起。
- **以为发布验收就是一次检查**：关键路径要进自动化测试，上线后还得持续回归和监控。

## 一句话总结

> **Copilot 上线前，成功、失败、审批、组合、回放这几条路径都得验收通过。**
