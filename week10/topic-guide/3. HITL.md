# 导学 03：人工审批怎样介入，又不拖住整个 Agent？

## 一句话理解

人在回路的核心是在高风险动作执行前把决策权交给人，同时不让 Agent 干等着。靠的是异步通知、状态保存和任务恢复。

## 用生活打比方

继续我们的物流配送中心。高价值包裹、危险品、不可撤销的操作，这些得转主管审批。系统先把当前订单状态、待执行动作和申请理由存下来，然后通知有权限的主管。员工不用守在审批台前等着，可以接着处理别的订单。主管批了，系统校验权限后从保存点恢复任务继续跑；拒了或者超时没处理，就按预案停掉、升级或转人工柜台。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **人在回路（Human in the Loop）** | 系统把特定动作的决定权交给有权限的人，过程全程记录。 |
| **风险触发矩阵（Risk Trigger Matrix）** | 代码里列明哪些动作必须审批，哪些异常要升级处理。 |
| **检查点（Checkpoint）** | 把当前任务状态和待执行动作存起来，等审批完了能从原处接着跑。 |
| **异步审批（Asynchronous Approval）** | 请求发出去之后释放 Agent 资源，审批结果回来了再恢复任务。 |
| **服务约定（Service Level Agreement）** | 约定审批最长等多久，到期后是升级、拒绝还是转人工。 |
| **追加式审计（Append-only Audit）** | 审批记录只能往后追加，不能改旧的，方便还原完整责任链。 |

## 避坑提醒

- **以为加个确认按钮就是人在回路**：生产级的人审还得覆盖权限校验、等待超时、状态恢复、降级处理和全程审计，一个弹窗远远不够。
- **以为 Agent 原地等待就是最简单的方案**：同步等待会占住执行资源，正确做法是存好状态、释放资源、等结果回来再恢复。
- **以为模型自己判断是否送审就是足够稳妥**：财务操作、不可逆动作、合规相关的事情，必须由代码规则强制拦截。
- **以为审批没有回来就是继续等待**：没有超时路径会让任务挂死，必须预设升级、自动拒绝或转人工。

## 一句话总结

> **靠谱的人审流程要能交出决策权、释放资源、审批后恢复现场，并且全程留痕。**
