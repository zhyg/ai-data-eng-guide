# 导学 03：人工审批怎样介入，又不拖住整个 Agent？

## 一句话理解

人在回路是在高风险动作前后移交决策权，并通过异步通知、状态保存和恢复机制完成审批。

## 用生活打比方

继续我们的物流配送中心。高价值包裹、危险品和无法撤销的操作要转主管审批。系统先保存订单状态、待执行动作和申请理由，再通知有权限的主管。员工不用守在审批台前，可以继续处理其他订单。主管批准后，系统校验其岗位权限，从保存点恢复任务；拒绝或久未处理时，则按预案停止、升级或转人工柜台。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **人在回路（Human in the Loop）** | 系统把特定动作的决定权交给有权限的人，并保存完整过程。 |
| **风险触发矩阵（Risk Trigger Matrix）** | 由代码列明哪些动作必须审批，哪些异常情况需要升级。 |
| **检查点（Checkpoint）** | 把当前任务状态和待执行动作保存下来，稍后可以从原处继续。 |
| **异步审批（Asynchronous Approval）** | 发出申请后释放 Agent 资源，审批结果到达时再恢复任务。 |
| **服务约定（Service Level Agreement）** | 规定审批等待边界，以及到期后升级、拒绝或转人工的处理。 |
| **追加式审计（Append-only Audit）** | 审批记录只能继续添加，不能覆盖旧内容，便于还原责任链。 |

## 避坑提醒

- **以为确认按钮就是人在回路**：生产审批还要覆盖权限、等待边界、恢复、降级和全程审计。
- **以为 Agent 原地等待就是最简单**：同步等待会占用执行资源，应保存状态并异步恢复。
- **以为模型自己判断是否送审就是足够稳妥**：财务、不可逆和合规动作要由代码规则强制拦截。
- **以为审批没有结果就是继续等待**：没有到期路径会让事务挂死，必须预设升级、拒绝或转人工。

## 一句话总结

> **可靠的人审流程要能移交权力、释放资源、恢复现场，并留下完整责任记录。**
