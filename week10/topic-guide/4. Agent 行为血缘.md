# 导学 04：Agent 做错后，系统能还原它当时为何这样做吗？

## 一句话理解

Agent 行为血缘把每次动作与所用数据、证据、提示、工具、模型、审批和结果关联起来。

## 用生活打比方

继续我们的物流配送中心。包裹追踪记录每次扫描发生在哪个环节、由谁操作、依据哪张作业单，以及当时使用的规则版本。若包裹走错路线，管理人员能沿同一追踪编号还原调度、审批和交接过程，还能找到当时看到的订单状态。只记最终签收结果，无法解释中途为何改道。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **行为血缘（Action Lineage）** | 记录 Agent 做了什么，以及这个动作依赖了哪些信息和规则。 |
| **追踪标识（Trace ID）** | 给同一任务链分配共同标识，用来串起调用、数据和审计记录。 |
| **数据快照（Data Snapshot）** | 保存动作发生时所见的数据状态，避免后来数据变化后无法复现。 |
| **证据片段（Evidence Chunk）** | 锁定回答或决策引用的具体资料位置及其当时版本。 |
| **动作绑定（Action Binding）** | 把数据、证据、提示、工具和模型的版本一起挂到动作上。 |
| **动作回放（Action Replay）** | 用保存的现场重新运行或检查决策，定位差异和责任。 |

## 避坑提醒

- **以为数据血缘就是行为血缘**：数据来源只能解释输入，行为血缘还要记录动作、依据、版本和审批。
- **以为调用链就是完整现场**：服务调用能显示经过哪里，却不能单独回答模型依据什么作出决定。
- **以为保存最终结果就是能够复现**：缺少当时的数据快照、证据和各项版本，后来只能猜测。
- **以为各系统分别记录就是可以追查**：没有共同追踪标识，数据、调用和审计事件很难可靠关联。

## 一句话总结

> **行为血缘的验收标准是能可靠回放动作现场，并解释做了什么、依据什么、由谁批准。**
