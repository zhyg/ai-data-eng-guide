# 导学 04：Agent 做错后，系统能还原它当时为何这样做吗？

## 一句话理解

行为血缘就是给 Agent 的每次动作建档：它用了什么数据、看了什么证据、走的哪个提示词、调了哪个工具、哪个模型版本、谁批准的、结果是什么。

## 用生活打比方

继续我们的物流配送中心。包裹追踪记录会写明每次扫描发生在哪个环节、谁操作的、依据哪张作业单，以及当时用的规则版本。如果包裹走错了路线，管理人员能沿着同一个追踪编号，把调度、审批、交接过程一步步还原出来，还能查到当时看到的订单状态。只记最终签收结果的话，中途改道的原因就查不到了。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **行为血缘** | 记录 Agent 做了什么，以及这个动作依赖了哪些信息和规则。 |
| **追踪标识（trace_id）** | 同一任务链共享一个标识，用来把调用、数据和审计记录串起来。 |
| **数据快照** | 保存动作发生时看到的数据状态，不存的话数据后来变了就没法复现。 |
| **证据片段（Evidence Chunks）** | 锁定回答或决策引用的具体资料位置和当时版本。 |
| **五元绑定** | 把数据、证据、提示词、工具版本和模型版本一起挂到这次动作上。 |
| **动作回放（Action Replay）** | 用保存的现场重跑或检查当时的决策，定位问题出在哪、责任在谁。 |

## 避坑提醒

- **以为数据血缘就是行为血缘**：数据血缘只解释输入从哪来，行为血缘还要记动作本身、决策依据、各组件版本和审批过程。
- **以为有调用链就是有完整现场**：调用链能告诉你请求经过了哪些服务，但回答不了模型是根据什么做出决定的。
- **以为保存最终结果就是能够复现**：缺了当时的数据快照、证据片段和各项版本信息，事后只能猜。
- **以为各系统分别记录就是可以追查**：没有共同的追踪标识，数据日志、调用日志和审计事件散落在不同地方，查起来很痛苦。

## 一句话总结

> **行为血缘够不够用，看出了问题能不能回放当时的现场，说清楚做了什么、根据什么、谁批准的。**
