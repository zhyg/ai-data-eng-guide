# 导学 06：开业前怎样证明 Copilot 全链路真的可用？

## 一句话理解

端到端实践就是把前面各模块组装起来，然后用契约测试、故障演练、审批恢复、血缘回放和健康检查来验收。

## 用生活打比方

继续我们的物流配送中心。开业前要做全链路演练：普通订单能不能正确分流和交付，重复提交的作业单会不会造成重复出库，没权限的员工能不能被拦住，查询系统挂了能不能回退到备用方案，高风险包裹能不能暂停、等批准后再恢复。演练还要核对每次扫描、审批和执行结果能不能沿追踪编号还原出来，运行指标有没有达到团队定的目标。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **工具注册表（Tool Registry）** | 集中存放所有可用工具和它们的契约，路由和执行环节都看同一份。 |
| **契约测试（Contract Test）** | 故意输入缺字段、越界值、未知内容，看工具会不会老老实实拒绝。 |
| **健康检查（Health Check）** | 持续检查工具、证据、审批和回答质量是否达标。 |
| **审批恢复（Approval Resume）** | 审批结果回来后校验审批人身份，然后从保存的状态继续往下跑。 |
| **统一追踪（Unified Tracing）** | 用同一个追踪标识把路由、工具、回退、审批、数据和审计全部关联起来。 |
| **发布门槛（Release Gate）** | 提前定好必须通过的路径和检查项，没过就不准发布。 |

## 避坑提醒

- **以为模块分别可用就是全链路可用**：模块和模块之间的连接处也会出问题，得从用户请求一路验到响应和监控。
- **以为契约测试只检查必填字段**：未知字段、取值边界、权限、重复请求、失败码映射都得覆盖。
- **以为批准动作就是审批结束**：后面还有校验审批角色、恢复检查点、执行动作、记录完整事件这一串。
- **以为追踪标识能关联日志就是可以回放**：回放需要的是当时的数据快照、证据片段、提示词版本、工具版本和模型版本。
- **以为健康指标达标就是可以停止检查**：上线之后仍然要持续监控、定期回归。

## 一句话总结

> **发布前用可重复的全链路测试证明系统受控、可恢复、可审计，故障时也能给出预定结果。**
