# 导学 06：开业前怎样证明 Copilot 全链路真的可用？

## 一句话理解

端到端实践把各模块组装起来，并用契约测试、故障演练、审批恢复、血缘回放和健康检查完成验收。

## 用生活打比方

继续我们的物流配送中心。开业前要做全链路演练：普通订单能否正确分流和交付，重复作业单会不会造成重复出库，无权限员工能否被拦住，查询系统故障时能否回退，高风险包裹能否暂停并在批准后恢复。演练还要核对每次扫描、审批和结果能否沿追踪编号还原，并确认运行指标达到团队设定目标。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **工具注册表（Tool Registry）** | 集中保存可用工具及其契约，供路由和执行环节按同一份信息工作。 |
| **契约测试（Contract Test）** | 主动输入缺字段、越界值和未知内容，确认工具会拒绝不合规请求。 |
| **健康检查（Health Check）** | 持续检查工具、证据、审批和回答质量是否达到团队目标。 |
| **审批恢复（Approval Resume）** | 审批结果到达后，校验审批人并从保存状态继续执行。 |
| **统一追踪（Unified Tracing）** | 用共同追踪标识关联路由、工具、回退、审批、数据和审计。 |
| **发布门槛（Release Gate）** | 预先规定必须通过的路径和检查项，未满足就不发布。 |

## 避坑提醒

- **以为模块分别可用就是全链路可用**：模块连接处也会出错，要从用户请求一直验证到响应和监控。
- **以为契约测试只检查必填字段**：未知字段、取值边界、权限、重复请求和失败码映射都要验证。
- **以为批准动作就是审批结束**：还要校验审批角色、恢复检查点、执行动作并记录完整事件。
- **以为追踪标识能关联日志就是可以回放**：回放还需要当时的数据、证据、提示、工具和模型信息。
- **以为健康指标达标就是可以停止检查**：上线后仍要持续监控、回归和治理。

## 一句话总结

> **发布前应以可重复的全链路测试证明系统受控、可恢复、可审计，并能在故障下给出预定结果。**
