# 导学 01：Agent 会调用工具，就能放心让它执行吗？

## 一句话理解

工具契约是一组运行时规则，管住 Agent 能调什么、怎么调、谁能调、调重了怎么办、调完怎么查。

## 用生活打比方

把 Agent 想成物流配送中心的新员工。查件、改址、出库，每项操作都有标准作业单，写清楚边界在哪。每票订单带唯一编号，就算网络抖动重复提交，也不会真的出两次库。员工只能碰自己岗位权限内的环节，每次扫描和修改都留下操作人、结果和追踪编号。但光把作业单写清楚不够，系统得在操作时实际校验，不能指望员工自己记住规矩。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **受控工具** | 带运行时护栏的操作入口，比如改地址前会检查参数、身份和订单状态。 |
| **结构约束（Schema）** | 规定必须填什么、允许填什么、结果长什么样，契约外的内容直接拒绝。 |
| **幂等** | 同一请求送达多次也只产生一次业务效果，专治网络重试和 Agent 反复调用。 |
| **权限** | 工具自己核对调用方身份和岗位，不通过就停。 |
| **审计事件** | 每次调用都结构化记录谁调的、传了什么、结果如何、追踪标识是什么。 |
| **失败码** | 用固定类别说明失败原因，Agent 拿到后能按预定方式重试、回退或停下来。 |

## 避坑提醒

- **以为参数格式正确就是调用安全**：格式校验挡不住越权和业务越界，角色、动作范围、状态规则都得查。
- **以为写操作成功就是可以随便重试**：网络重发和 Agent 重试都可能让操作再生效一次，写类工具必须有去重机制。
- **以为有日志就是有审计**：普通文本日志很难关联到具体责任人，审计要求结构化保存操作人、参数摘要、结果和追踪标识。
- **以为模型信心高就是可以执行高风险动作**：外部不可逆操作和涉及资金的动作，仍然要进人工审批。

## 一句话总结

> **输入、去重、权限、审计都管住了，工具才算具备生产准入条件。**
