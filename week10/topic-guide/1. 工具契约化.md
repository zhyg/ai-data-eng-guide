# 导学 01：Agent 会调用工具，就能放心让它执行吗？

## 一句话理解

工具契约是在运行时约束 Agent 调用范围、输入、权限、重复执行和留痕方式的一组规则。

## 用生活打比方

把 Agent 想成物流配送中心的新员工。每项操作都有标准作业单，查件、改址和出库各有明确边界。每票订单带唯一订单号，重复提交不会重复出库。员工只能操作岗位权限内的环节，每次扫描和修改都会留下操作人、结果与追踪编号。标准作业单写得再清楚，也要由系统在操作时校验，不能只靠员工记住。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **受控工具（Controlled Tool）** | 带运行时护栏的操作入口，比如改地址前会检查参数、身份和订单状态。 |
| **输入输出约束（Schema）** | 规定必须填写什么、允许填什么以及结果长什么样，契约外内容会被拒绝。 |
| **幂等（Idempotency）** | 同一请求重复送达也只产生一次业务效果，避免重试造成重复执行。 |
| **权限校验（Permission Check）** | 工具自己核对操作人和岗位，未获授权就停止执行。 |
| **审计事件（Audit Event）** | 每次调用都结构化记录操作人、参数摘要、结果和追踪标识，方便追查。 |
| **失败码（Failure Code）** | 用固定类别说明失败原因，让 Agent 能按预定方式重试、回退或停止。 |

## 避坑提醒

- **以为参数格式正确就是调用安全**：格式校验挡不住越权和业务越界，还要检查角色、动作范围与状态规则。
- **以为写操作成功就是可以放心重试**：网络重发和 Agent 重试可能再次生效，写类工具要有去重机制。
- **以为调用日志就是完整审计**：普通文本日志难以关联责任，审计还要保存操作人、参数摘要、结果和追踪标识。
- **以为模型把握很大就是可以执行高风险动作**：外部不可逆和财务动作仍要进入人工审批。

## 一句话总结

> **工具只有同时管住输入、重复执行、权限和审计，才具备生产准入条件。**
