# 导学 02：工具越多，为什么越要收回模型的选择权？

## 一句话理解

工具路由与失败回退用规则、窄范围判断和预设降级路径，控制 Agent 选什么工具以及失败后怎么继续。

## 用生活打比方

继续我们的物流配送中心。调度台先按任务类型分流：查件进入查询通道，改地址进入订单维护通道，出库进入仓库作业通道。系统只把相关岗位交给员工选择。实时查询故障时，系统先按规则重试，再读取标明更新时间的缓存，仍无法处理就通知值班人员，最后向客户返回统一说明。高风险出库则走固定流程，不由员工临时改步骤。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **工具路由（Tool Routing）** | 根据请求类型和风险，把任务送到合适的工具或固定流程。 |
| **规则加模型（Rules plus LLM）** | 代码先缩小候选范围，再让模型处理少量确实需要判断的选择。 |
| **显式工作流（Explicit Workflow）** | 由代码写明执行顺序，模型只在限定环节内判断。 |
| **失败回退链（Fallback Chain）** | 主工具失败后，按预设顺序重试、使用备用结果、转人工或降级响应。 |
| **优雅降级（Graceful Degradation）** | 完整服务暂时不可用时，返回有限但可信的结果，并说明限制。 |
| **证据锚点（Evidence Anchor）** | 知识查询返回的具体来源位置，便于核对答案依据。 |

## 避坑提醒

- **以为把所有工具交给模型就是更灵活**：候选越杂，查询和写入越容易误选，应先用规则缩小范围。
- **以为工具失败就是继续重试**：无上限重试会占住资源，每类失败都要有停止条件和下一条路径。
- **以为缓存结果就是实时结果**：缓存必须标明已经过时，避免用户按旧状态继续操作。
- **以为知识检索就是独立系统**：把它包装成受控工具，才能复用路由、回退和审计规则。

## 一句话总结

> **风险越高、流程越明确，控制权越应放在代码和可测试的工作流中。**
