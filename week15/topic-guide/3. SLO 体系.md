# 导学 03：系统到底算不算好，谁说了算？

## 一句话理解

服务等级目标把可用性、速度、回答质量、合规和成本写成工程、业务与合规共同认可的运行契约，并用错误预算决定何时继续变更、何时暂停。

## 用生活打比方

继续我们的连锁餐厅。门店运营一段时间后，总部会问服务到底好不好。只说最近评价不错，无法指导厨房排班、菜单调整和食品安全管理。

餐厅需要一份共同签署的运营约定：正常营业时订单要能完成，出餐等待要在可接受范围内，菜品要符合配方并标明过敏原，食品安全问题不得放过，每份订单的成本也要受控。指标达到约定水平后，门店可以把精力放到新菜和流程改进上，无需无限追求更快。

约定还会留出可接受的波动空间。波动空间消耗太快，门店先暂停非必要的菜单调整，集中处理稳定性问题；空间充足时，可以试做新菜。标准来自历史表现、顾客能接受的下限和运营能力，再经过试运行后由相关负责人确认。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **服务等级目标（SLO）** | 团队对服务运行水平作出的明确约定，规定可用性、响应速度、回答质量、合规和成本要达到什么范围，以及未达标时采取什么动作。 |
| **关键绩效指标（KPI）** | 用来衡量业务结果的目标，常常希望持续提高。它通常不包含达到目标后可以停止优化的边界，也不负责定义系统失误时的工程动作。 |
| **忠实度（Faithfulness）** | 检查回答是否得到所提供证据的支持。比如答案增加了证据里没有的结论，忠实度就会下降。 |
| **引用覆盖率（Citation Coverage）** | 检查需要证据支撑的回答是否都带有来源引用。它关注有没有依据可查，不只关注答案读起来是否流畅。 |
| **拒答率（Refusal Rate）** | 统计系统因为不确定、权限或安全原因拒绝回答的情况。过高可能影响可用性，过低又可能让系统在证据不足时乱答。 |
| **错误预算** | 在约定周期内允许服务偏离目标的总空间。预算快用完时暂停增加风险的变更，预算充足时可以开展更积极的实验。 |
| **燃烧率（Burn Rate）** | 衡量错误预算消耗速度的指标。短时间快速消耗用于发现突发故障，持续偏快用于发现缓慢退化。 |
| **SLO as Code** | 把服务目标写成可版本管理的机器可读文件，再自动生成告警和门禁规则，让目标能评审、执行和追溯。 |

## 避坑提醒

- **以为 SLO 就是换个名字的 KPI**：KPI 常追求越高越好，SLO 会定义达到即可的边界和错误预算。混用后，工程团队会持续追逐业务难以感知的提升。
- **以为可用性和延迟达标就代表 AI 服务可靠**：系统在线且响应很快，仍可能给出没有证据的答案。SLO 还要覆盖忠实度、引用、拒答、合规和成本。
- **以为阈值定得越高越专业**：脱离历史表现和业务可接受范围的目标会带来很高的工程成本。应先收集实际数据，再试运行并共同签署。
- **以为写下目标就足够了**：没有错误预算、消耗速度和自动动作，未达标时团队仍不知道该继续发布还是先处理稳定性问题。
- **以为普通质量提升可以抵消合规问题**：隐私泄露等红线要单独判断，不能与其他指标取平均，也不能因回答质量较好而放行。

## 一句话总结

> **SLO 要从历史与业务边界中制定，并同时绑定错误预算、告警和变更策略，才能成为可执行的服务契约。**
