# 导学 03：数据全有了，为什么盯着一墙图还是看不出问题？

## 一句话理解

仪表盘是把海量 trace 数据浓缩成少量面板的过程，关键是为不同角色设计不同视图，并支持从总览逐层钻取到具体 trace。

## 用生活打比方

继续我们的快递追踪系统。每天几十万条扫码记录汇到总部，如果把所有数据平铺在一面墙上，密密麻麻的曲线谁也看不清。快递公司的做法是给不同角色配不同屏幕：调度主管看整体面板（今天全网准时率多少、哪条线路爆了），具体站长看自己站的分拣效率和异常件，客服看单个投诉件的流转路径。调度主管发现准时率掉了，点进去能看到是哪条线路出了问题，再点进去能看到具体哪个站卡住了。这种"总览→拆解→详情"的层级就是仪表盘设计的核心。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **5 个必备面板** | 总览（Overview）、质量（Quality）、性能（Performance）、成本（Cost）、错误（Errors），缺一张就有一块盲区。 |
| **Day-over-Day 对比** | 把今天的指标和上周同一天同时段比，而不是只看当前绝对值。绝对值会骗人，变化率才能发现真异常。 |
| **三层钻取** | 从总览面板发现异常 → 点进去看是哪类错误/哪段慢 → 再点进具体 trace 看时间轴 → 决定回滚还是修。 |
| **分角色定制** | oncall 要红绿灯式的快速判断，工程师要 span 级拆解，PM 要业务趋势和成本，三者不能混在同一个视图。 |
| **面板双向跳转 trace** | 面板上任何一个异常点都能一键跳到对应的 trace 列表，点不进去的面板等于断了诊断链路。 |

## 避坑提醒

- **以为面板越多越专业**：面板太多反而让值班人员找不到重点，凌晨三点被叫醒时需要的是几张红绿灯，不是一面墙的曲线。
- **以为看实时数字就够了**：今天 P99 是 2.1 秒，高还是低？没有对比没有答案。和上周同时段比，才能判断是正常波动还是真退化。
- **以为 P99 好就代表用户体验好**：P99 只反映最慢的那批，中位体验（P50）掉了大部分用户都受影响，两个指标要同时看。
- **以为面板只要好看就行**：面板的价值在于能一键跳到 trace 详情。如果看到异常还得另开工具重新搜，排障效率直接打折。

## 一句话总结

> **仪表盘是为决策设计的，少量面板加三层钻取，让值班人员迅速判断系统健不健康，再点两下就能定位到具体 span。**
