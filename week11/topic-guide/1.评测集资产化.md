# 导学 01：模型答得对不对，凭什么下结论？

## 一句话理解

评测集是一套版本化、分层覆盖、能反复使用的题库，用来客观衡量模型答得好不好。

## 用生活打比方

把给模型做质检想成给一所学校建考试体系。第一步是攒一套好题库。好题库要分层：大部分考高频基础题，一部分考容易混淆的边界题，还要专门留一批陷阱题，看学生会不会被诱导写出不该写的内容，再加几道需要跨章节推理的综合题。题库要标好版本，历年错题单独存档，每道题都配好标准答案和对应的课本出处。这样明年、后年都能拿同一套题横向比。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **评测集（数据资产）** | 一套需要长期经营的样本集合，能标版本号、能反复跑回归、能用来对抗攻击、能做治理审计。 |
| **四类样本** | 高频典型样本（happy）、边界长尾样本（boundary）、对抗反例样本（adversarial）、多跳综合样本（multi-hop），少一类就有一块盲区。 |
| **反例库（Adversarial）** | 专门收集诱导越权、诱导泄露隐私、误导攻击这类样本，来自踩过的坑和红队攻击，是评测集里最值钱的部分。 |
| **问题-答案-证据三元组** | 每条样本不只有问题和标准答案，还要标明答案该引用哪段原文当证据。 |
| **发布清单绑定（release manifest）** | 把这次发布用了哪版评测集写进发布记录，锁住版本才能比较上线前后。 |

## 避坑提醒

- **以为做过一版评测集就是有了质量保障**：业务在变、模型在升级、系统底座在迭代，昨天的标准答案今天可能已经过时，评测集要跟着持续更新。
- **以为样本数量多就是覆盖好**：只堆常见问题等于只覆盖正常场景，碰到诱导攻击就崩，分层覆盖比单纯追求数量重要。
- **以为全自动生成就是省了标注**：模型擅长造正常问答，造不出真实的攻击意图和边界情境，反例样本要从历史事故和红队测试中人工补充。
- **以为有问题和答案就是一条合格样本**：缺了证据出处就没法验证引用是否正确，缺了分类标签就没法定位到底哪类场景在丢分。

## 一句话总结

> **先把评测集做成分层、可版本、带证据的资产，后面的指标计算、裁判校准、门禁阻断才有立足点。**
