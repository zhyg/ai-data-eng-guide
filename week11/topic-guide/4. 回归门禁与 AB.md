# 导学 04：评测报告拦不住上线，做它还有什么用？

## 一句话理解

把评测从「事后看的周报数字」变成「事中卡住合并和发布的闸门」，退化超标就自动阻断。

## 用生活打比方

继续我们的学校考试体系。题库、成绩单、阅卷都有了，可如果考得再差也能照常升级毕业，这套考试就是摆设。所以要设门槛：平时小考不过关，作业不许提交；期末大考不过关，不许毕业；就算放出去实习，也先小范围试岗，表现不行立刻召回。要判断新教法比老教法好，还得对比足够多的班级、用两套独立方法验证，不能凭一个班几个人的成绩就下结论。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **评测驱动开发（Eval-Driven Development）** | 把评测做成开发流程里的硬约束，不过评测就不能合并、不能发布。 |
| **评测体系成熟度（L0-L4）** | 从没评测、到周报、到自动跑但不拦、再到带门禁、直至全链路自动升降档，越往后拦得越多。 |
| **三层门禁** | 合并前的 PR 门禁、发布前的 Pre-Release 门禁、上线后的灰度（Canary）门禁，各拦一类问题。 |
| **A/B 测试** | 新旧两版跑同一批题比高低，用来做上线选型决策。 |
| **双重统计检验** | 同时用参数和非参数两种检验，两个都显著才算数，避免分数分布不正态时误判。 |
| **自动回滚** | 灰度期间指标一旦跌破红线，系统自动退回旧版，不等人工处理。 |

## 避坑提醒

- **以为有警告就是有门禁**：警告没人看，能拦住的就别只提醒，温柔的门禁等于没门禁。
- **以为拍脑袋定阈值就是有标准**：定松了漏退化，定紧了老误报，要基于历史波动来定。
- **以为平均分没跌就是没退化**：平均看着还行，某一类可能已经暴跌，要看分位和分人群。
- **以为跑几条就是做了 A/B 测试**：样本太少方差大，真退化可能看着像进步，要事前算够样本量。
- **以为配了告警就是有自动保障**：告警半夜没人响应，坏版本会一直放着，得配自动回滚。

## 一句话总结

> **评测只有能阻断合并和发布，才真正有牙齿；不能阻断的评测只是装饰。**
