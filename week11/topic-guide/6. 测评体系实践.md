# 导学 06：把这套评测体系，真跑通一遍是什么样？

## 一句话理解

把评测集、指标、裁判、门禁、业务 SLO 串成一条链路，让评测报告真正参与发布决策。

## 用生活打比方

继续我们的学校考试体系。前几讲把题库、成绩单、阅卷、门槛、业务目标一件件准备好了，这一讲是期末统考，把整套流程从头到尾走一遍。先检查各项材料是否齐备合规，再用固定的标准卷离线跑一遍确认流程通，然后拿新成绩和历史基线比有没有退步，接着用标准卷校准阅卷老师，最后把这次的质检结果写进毕业档案，作为能不能放行的依据。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **黄金测试集** | 一份标好标准答案、关键词、证据和拒答条件的样本集，作为评测的基准。 |
| **对象模型** | 把散乱的样本、预测、评分、报告统一成结构化对象，后续都操作统一对象，不再碰零散文件。 |
| **内容指纹（digest）** | 对题库内容做哈希，任何改动都会变，用来保证每次发布用的题库版本一致。 |
| **契约测试** | 先校验题库、预测样例、发布清单是否符合约定结构，不合格后面的评分就没意义。 |
| **回归门禁（regression）** | 拿当前报告和历史基线比，退化超阈值就阻断。 |
| **发布清单（release manifest）** | 把评测集、校准结果、业务 SLO 和部署一起绑进发布记录，纳入治理。 |

## 避坑提醒

- **以为产出报告就是做了评测**：目标是让报告参与发布决策，报告躺在文档里等于没做。
- **以为跳过契约检查就是省了步骤**：基础材料不符合约定结构，后面的评分全不可靠，省的那步会让后面全白跑。
- **以为校准过一次就是永久可信**：模型或样本一变就得重新校准，上次的结论不能直接搬。
- **以为离线跑通就是上线没问题**：离线用固定样本稳住流程，真实流量的问题还得靠门禁和灰度接着拦。

## 一句话总结

> **评测体系的完整形态，是让每次发布都带着可复现、可阻断、可追溯的质检结论放行。**
