# 4. 回归门禁与 A/B

## 核心问题

前三节建好了评测集 / 指标 / 裁判，这一讲让它们真正咬合进生产：把评测从「周报数字」变成「PR 能不能合并」的硬约束。

真实场景：一个团队评测做得挺像样，RAGAS 跑着、看板挂着，每周五给老板汇报漂亮的趋势图，可线上质量该退化还退化。为什么？因为那份评测从来没拦住过任何一个 PR——工程师改完 prompt 直接合并上线，评测周一才跑，发现退化时客户已经骂了一个周末。

关键判断：不阻断的评测等于没有评测，它只是一份「美化过的日志」。评测真正的力量是变成「PR 能不能 merge」的那道闸。这就是「评测驱动开发」（Eval-Driven Development）的核心：把评测从「事后看的数字」做成「事中卡的闸门」。

## 评测体系成熟度的 5 个等级

大多数团队卡在 L1-L2，升到 L3 的工程量不大，但效果是质变。

| 等级 | 具体表现 | 能拦住什么 | 能避免什么 |
| :--- | :--- | :--- | :--- |
| L0 无评测 | 凭感觉抽测 | 什么都拦不住 | —— |
| L1 周报评测 | 每周跑一次给老板看 | 只能看趋势 | 退化 1 周后才发现 |
| L2 PR 评测（无门禁） | PR 时自动跑但不阻断 | 看到问题靠人推动 | 靠人记得检查 |
| L3 PR 评测 + 门禁 | 退化 > 阈值 = 不能合并 | 90% 退化 | 生产事故 |
| L4 PR + 上线 + Canary | Canary 自动升档 / 回滚 | 99% 退化 | 客户感知到问题 |

L1（周报）和 L2（PR 跑但不拦）是最大的两个坑——看着有评测，其实没牙。从 L2 升到 L3 往往就是加一个 exit 1、几十行 CI 脚本的事，却把「质量保障」从「靠人自觉」变成「系统强制」，是 Demo 团队和生产团队的分水岭。

## 评测门禁的 3 个层级

一个变更要过哪几道闸，越往后样本越多、决策越慢、拦的问题越接近真实流量。

| 门禁 | 触发时机 | 跑什么 | 判定 | 决策时长 |
| :--- | :--- | :--- | :--- | :--- |
| PR Gate | 改 prompt / 索引 / Skill | golden set 50-200 条 | 退化 > 2% → block | 5-10 分钟 |
| Pre-Release Gate | 合到 main 后 | 全指标 + 反例库 1000+ 条 | 退化 > 1% → 阻塞发布 | 20-30 分钟 |
| Canary Gate | 上线后 5% 流量 | quality + latency + cost | 退化触发自动回滚 | 动态观察 30-60 分钟 |

三道闸缺一不可：PR Gate 拦「改坏了」，Pre-Release 拦「全量才暴露的退化」，Canary 拦「只有真实用户流量才能发现的问题」。PR Gate 对反例库要「零退化」——安全类指标比性能类严。

## PR 评测门禁的落地要点

把评测从「周报」升级成「PR 能不能合并」，靠一套 CI（GitHub Actions / GitLab CI）：

- **paths 触发条件**：只有改了 prompt / tools / chunk / retrieval 才跑，不浪费 CI 资源。
- **参数化阈值**：每个指标单独设 `--max-drop`（如 faithfulness=0.02、context_precision=0.03），写在命令行不硬编码进代码。
- **反例库零退化**：`--no-drop adversarial_pass_rate`，安全类一条都不许退。
- **结果贴回 PR**：把报告 comment 在 PR 里，review 时一眼看到影响，不用翻 CI 日志。
- **失败即阻断**：退化超阈值 → exit 1 → block PR，这一行是灵魂，评测从此有了「否决权」。2026 年 Braintrust 把这套做成开箱即用的 GitHub Action。

## A/B 测试：上线决策要的是「新旧哪个更好」

评测告诉你「绝对分」，但上线决策要比出新旧优劣。RAG 的 A/B 有特别的坑：样本量、统计检验、分布非正态。

| 对比维度 | 具体例子 | 看哪些指标 | 建议样本量 |
| :--- | :--- | :--- | :--- |
| Chunk 策略 | fixed-512 vs semantic chunking | context_precision / recall | 300+ |
| Rerank 模型 | bge-reranker vs Cohere Rerank | CP + latency + cost | 500+ |
| Prompt 版本 | v3.2.0 vs v3.2.1 | F / AR / hallucination | 200+ |
| LLM 模型 | GPT-5 vs Claude Sonnet 4.6 | 6 指标 + 成本 | 1000+ |

样本量不是「越多越好」，是「够用就好」，按效应大小（effect size）事前算：大效应（>10% 改善）80 条够，中效应（5%）要 200 条，小效应（2%）得 800 条。别上来就「跑 30 个看看」——30 个样本的方差能让一个真退化看着像进步。

## 样本量计算 + 双重统计检验

把「看图说话」变成「自动决策」，RAG 分数常非正态，必须双重验证：

- **事前算样本量**：按 effect size / alpha / power 求所需样本数，避免跑了几百条才发现样本不够白跑。
- **t-test + Mann-Whitney 双重检验**：t-test 基于正态假设，Mann-Whitney 是非参数、更鲁棒；两个 p 都 < 0.05 才算显著，比单一检验稳得多。
- **直接给决策**：输出 ship_B / keep_A / need_more_data 三选一，不是「看图说话」。
- CI 里直接调这套，A/B 报告 + 决策建议一体化，把「拍脑袋上线」挡在门外。

## Canary 灰度：上线后的最后一道门

有些问题只有真实用户流量才暴露，PR / Pre-Release 都拦不住。让 5% 流量先跑，好就升档、差就秒回滚：

`Deploy 5% 流量 → Monitor 15-30 分钟实时收集指标 → 在线评测 + A/B 对比 → 自动决策升档/回滚 → 决策写入 release manifest`

Canary 是 Week 8 release manifest + Week 10 trace audit + Week 11 在线评测三者合起来才撑得住的「自动门」。它的价值在「自动」两个字——退化触发自动回滚，而不是「指标差了等人工处理」。踩过的坑：Canary 配了告警没配自动回滚，半夜 3 点指标崩了没人响应，等早上发现已经放了 6 小时坏版本。自动回滚那行代码，比任何告警都值钱。

## Industry Signals（2026）

Eval-Driven Development 已是工程范式，更是合规要求。没有 eval gate 的 AI 团队，要么没规模化，要么走在事故路上。

| 来源 | 能力 / 要求 | 工程含义 |
| :--- | :--- | :--- |
| Anthropic 内部 SOP | 每次模型/prompt/工具改动 → 触发 eval → 不过不上 | EDD 已是大厂日常 |
| Braintrust（2026 EDD 标杆） | GitHub Action 每个 PR 自动跑评测 + 贴评分 | 一行 Action 就上 eval gate |
| LangSmith / Langfuse / Phoenix | CI 集成 + trace + 自托管 | 不想自建，平台直接接 CI |
| EU AI Act（2026.5 Omnibus） | 高风险 AI 重大变更前必须有评测报告 | 高风险大限延至 2027.12.02，但评测义务不变 |

自动评测已从「工程提效」升级成「合规必备」。eval gate 现在不做，将来不是「要不要补」的问题，是「罚不罚款、能不能上线」的问题。

## Anti-Patterns：评测门禁的 5 个反模式

做对了，系统稳定性能差 10 倍。

| 反模式 | 具体表现 | 后果 | 正确做法 |
| :--- | :--- | :--- | :--- |
| warn 不 block | PR 有 warning 但能合并 | 90% 人忽略 → 退化上线 | 硬 block + 显示具体退化 |
| 阈值拍脑袋 | 「退化 5% 内算正常」 | 过松漏退化 / 过紧老报警 | 基于历史 P95 trend 定 |
| 只看 mean | 「mean -2% 还行」 | 某 segment 暴跌没看到 | 看 percentile + 分 segment |
| A/B 不算样本量 | 「跑 30 个差不多」 | 统计不显著瞎决策 | 事前算样本量 |
| Canary 不自动回滚 | 「指标差再人工处理」 | 半夜 3 点没人响应 | 阈值触发自动回滚 |

第 1 个「warn 不 block」最普遍也最坑：团队觉得先 warn 温柔点、别挡住开发，结果 warning 没人看，退化照样上线。硬规矩：能 block 的就别 warn。温柔的门禁等于没门禁——「看得到拦不住」是最差的中间态，既花了 CI 成本，又没拦住事故。
