# 2. RAGAS 多维量化

## 核心问题

上一讲做完了评测集这把尺子，这一讲给尺子刻上刻度：把「答得好不好」变成「F=0.892 / AR=0.913 / CP=0.870」这样能诊断、能对比的数字。

真实场景：太多团队质量只报一个数「答对率 80%」。但追问「错的那 20% 是模型编的、是答非所问、还是压根没检索到」，十有八九答不上来。问题就在这——「对/错」这一个维度，把三种完全不同的病混成了一锅。RAGAS 的精妙，就是把这一个「对错」拆成能分别下药的多个工程维度。

## 三层六指标：RAG 评测不能只用一个分数

只看「答对率」是新手做法，看 6 个维度才知道到底是哪一层在拖后腿。

| 层级 | 指标 | 回答什么问题 | 低了怎么办 |
| :--- | :--- | :--- | :--- |
| 检索层 | context_precision / context_recall | 资料找对了吗 / 找全了吗 | rerank / chunk / hybrid |
| 生成层 | faithfulness / answer_relevance | 有没有编 / 答没答到点 | prompt / query 改写 |
| 整体层 | answer_correctness / semantic_similarity | 综合对不对 / 跑没跑偏 | 回到上面拆根因 |

先看检索层——资料没找对，生成再强也是巧妇难为；再看生成层——资料对了还编，那是 prompt 的锅。

## 三大核心指标

阈值是工程经验值，不是绝对真理，按业务风险上调。

| 指标 | 层级 | 测什么 | 低值意味着 | 阈值 |
| :--- | :--- | :--- | :--- | :--- |
| Faithfulness 忠实度 | 生成层 | 答案每个 claim 是否都来自上下文 | LLM 在编造 | > 0.85（金融可拉到 0.92） |
| Answer Relevance 相关性 | 生成层 | 答案和提问意图的相关程度 | 答非所问 / 偏题 | > 0.80 |
| Context Precision 精准度 | 检索层 | 召回的 chunk 里真相关的占比 | 召回了太多噪声 | > 0.75 |

关键判断：Faithfulness 比 Answer Relevance 更重要，但很多团队反过来。因为「答非所问」用户一眼看穿，而「编得有理有据」最坑——它骗得过用户，却骗不过监管。金融场景，Faithfulness 是第一红线。

## RAGAS 6 个指标完整对照

这 6 个合起来 = RAG 系统的体检表，少跑一个就有盲区。

| 指标 | 层级 | 怎么算 | 低值意味着 |
| :--- | :--- | :--- | :--- |
| Faithfulness | 生成 | 逐句 claim 能否在 context 找到 | LLM 在编造 |
| Answer Relevance | 生成 | 答案与问题意图的语义匹配 | 答非所问 |
| Context Precision | 检索 | 召回 chunk 中相关的占比 | 召回噪声多 |
| Context Recall | 检索 | 该召回的 chunk 实际召回比例 | 漏召关键资料 |
| Answer Correctness | 整体 | F + AR + 与标答对照 | 综合差 |
| Semantic Similarity | 整体 | 与标答的 embedding 距离 | 语义跑偏 |

检索层 CP/CR 是一对，方向相反：CP 低 = 召回太脏，CR 低 = 召回太漏。很多人只跑 CP 不跑 CR，结果「召回很干净」却漏了一半关键资料，分数好看、答案残缺。两个一起看才不骗自己。

## 在项目里跑通 RAGAS 的要点

- 评测样本直接读 Lesson 1 的评测集，同一个 source of truth，不另起炉灶。
- 字段对齐 RAGAS schema：question / answer / contexts / ground_truth。
- 一次 `evaluate()` 跑完 6 个指标，避免对 RAG 服务多次重复调用，省钱省时。
- judge 模型是命门：用 GPT-5 评 GPT-5 写的答案就是自评，bias 极大；生产一定用不同 family 模型 cross-evaluate（Lesson 3 细讲），embedding 可用 bge-large 做 semantic。
- 结果直接落成表 / CSV，接到 Grafana / dashboard，评测结果要能被看见。
- 成本参考：一轮全量（150 样本 × 6 指标）API 成本约 $1-3，别为省这点钱跳过评测。

## 指标低了具体改什么

RAG 项目最高频用到的「诊断 → 治疗」对照表。指标低不要慌、更不要全部推倒重做，按表精准下药。

| 指标低 | 病根 | 应对动作 | 对应周次 |
| :--- | :--- | :--- | :--- |
| Faithfulness < 0.85 | LLM 编造 / 引用错位 | 加严 prompt + Structured Outputs | Week 8 L3/L4 |
| Answer Relevance < 0.80 | 答非所问 / 偏离意图 | Query 改写 / Multi-Query | Week 8 L1 |
| Context Precision < 0.75 | 召回噪声太多 | 加 reranker + 调阈值 | Week 8 L2 |
| Context Recall < 0.75 | 关键资料漏召 | 换 chunk 策略 / 上 hybrid | Week 7 L2 / 8 L1 |
| Answer Correctness < 0.70 | 综合错 | 拆 6 维定位根因，别瞎改整体 | 回到上面 |

新手一看总分低就重做整条链路，浪费一周还不一定好；老手先拆 6 维、定位到具体那一层，改一个 reranker、调一行 prompt，半天解决。

## RAGAS 之外还要测的指标

RAGAS 测的是「质量」；生产 RAG 还得测「性能 / 成本 / 安全」。

| 指标 | 为什么必须测 | 怎么测 |
| :--- | :--- | :--- |
| Latency P99 | 答得慢，用户直接跑光 | OpenTelemetry trace 统计（Week 12） |
| Cost per Query | 上线后费用失控的头号元凶 | token usage × 模型单价汇总 |
| Refusal Rate | 该拒的有没有拒 | 反例库 + 自动检查 |
| Citation Accuracy | 引用是否真的支撑 claim | Citations API + 人工抽样 |
| HITL Trigger Rate | 人工介入触发得过多 / 过少 | 从 Week 10 audit 统计 |

Cost per Query 是常被忽视的坑：一个 demo 阶段没人管成本的 RAG，上线后月账单冲到 $10 万+，一查是每次召回 top_k=20、还套三轮 LLM 重排。质量、性能、成本、安全四个轮子，缺一个车就翻。

## 生产级 RAG 评测看板

Copilot 的健康仪表盘统一展示 5 类指标：每周复盘、每月对基线、每次发布对上一版。

| 分区 | 指标 | 看什么 |
| :--- | :--- | :--- |
| Quality | RAGAS 6 指标 | 答得对不对 |
| Latency | P50 / P99 | 答得快不快 |
| Cost | 每查询成本 | 烧不烧钱 |
| Safety | 拒答率 / PII | 安不安全 |
| HITL | 人工介入率 | 稳不稳 |

单看 Quality 那一格，就像只量体温不量血压——看着没烧，可能血压早爆了。这套看板 Week 12 会接到全链路可观测里。

## Industry Signals（2026）

路线已经清晰：开源探索 + 平台门禁，两条腿走。

| 工具 | 定位 | 2026 怎么选 |
| :--- | :--- | :--- |
| RAGAS | RAG 4 指标 / 无需标注 / 轻量 | 快速探索首选，像用 pandas 做分析 |
| DeepEval | pytest 风格 / TDD / CI 集成 | 卡门禁首选，explore with RAGAS, gate with DeepEval |
| Braintrust | eval + CI/CD 门禁 / PR 自动评分 | 小团队免费档就能上 eval gate |
| Langfuse / Phoenix / LangSmith / TruLens | trace + eval 一体 / 自托管或平台 | 不想自建就上，自托管选 Langfuse |

## Anti-Patterns：RAG 评测最常见的 5 个反模式

| 反模式 | 具体表现 | 后果 | 正确做法 |
| :--- | :--- | :--- | :--- |
| 只看一个分数 | 「答对率 80% 还行」 | 没法定位问题 | 6+ 维度拆解 |
| 同模型自评 | GPT-5 判 GPT-5 答的对错 | systematic bias | cross-evaluate |
| 评测集太小 | < 30 样本就 ship | 指标方差大 | 至少 100 样本 |
| 指标无基线 | 「今天 0.89」然后呢 | 不知变好变差 | 永远和上一版对比 |
| 没有反例 | 只测 happy path | 上线被反例打爆 | 加入 Lesson 1 的 adversarial |

「同模型自评」最隐蔽——分数往往特别好看让你飘飘然，可生产里掉得最快，因为模型偏爱自己风格的输出。硬规矩：任何要拿去做决策的评测，判分的模型必须和被判的模型不是一家，这是 Lesson 3 的主题。
