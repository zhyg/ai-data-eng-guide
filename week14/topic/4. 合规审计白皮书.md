# 4. 合规审计白皮书

## 核心问题

2026 年 AI 系统上线最大的卡点，往往不是技术、不是预算，是合规。

真实场景：一个系统模型、评测、可观测全做到位了，demo 惊艳，业务方拍板要上。结果卡在合规——法务要一份「可解释 + 可追溯 + 可审计」的材料，团队没有，只能找律师、找合规顾问、照模板人工写，外部费用轻松 $20,000 到 $50,000、来回三周，拖了三个多月。

关键判断：2026 年，合规白皮书根本不该人工写。Week 11-14 你已经产出的那些工程材料（manifest + trace + 血缘 + 评测），自动汇聚一下就是白皮书。

本节四件事：

1. 2026 合规实况（重要）：美国 EO 14110 已废除、EU AI Act 精确时间线、中国 AI 标识法
2. 为什么合规白皮书应该「工程产物自动汇聚」，而不是人工写 3 周
3. 白皮书的 8 段标准结构 + 自动生成器，每段对应前面某一周的产物
4. 4 类合规红线 + 监管来查时的「30 秒响应」工作流

## 2026 合规变天了

这一页最重要：三个已经变化、但很多材料还在照抄旧版的事实。

| 地区 | 2024 旧认知（很多材料还在讲） | 2026 真实情况 |
| :--- | :--- | :--- |
| 美国 | 拜登 EO 14110 是硬要求 | EO 14110 已于 2025-01-20 被废除，联邦转去监管，别再引它 |
| 欧盟 | EU AI Act 2025 全面生效 | GPAI 执法 2026-08 起；高风险经 Digital Omnibus 推迟到 2027-12；AI 标识 2026-08 |
| 中国 | 生成式 AI 备案 + 安全评估 | 再加 AI 生成内容标识办法（GB 45438-2025，2025-09-01 起强制） |

「合规讲错」比「不讲」更糟——拿着一个已经被废除的行政令去跟法务对齐，直接翻车。

2026 的真实格局：美国联邦层面松了（约束主要来自加州等州法）；欧盟仍是最严，但高风险义务被推迟给了喘息期；中国这边最实在——C 端服务不光要备案，生成的内容还必须打「AI 生成」标识，微信、抖音、小红书全在管。

给国内团队的判断：今天上一个 C 端 AI 服务，备案 + 内容标识是硬门槛，这俩没有，平台直接不让你上。

## 主流合规框架

| 框架 | 适用范围 | 硬性要求 | 2026 状态 |
| :--- | :--- | :--- | :--- |
| EU AI Act | 欧盟市场 | 透明度 / 可解释 / 可追溯 / 监督 | 最严；高风险推迟到 2027-12 |
| 中国备案 + 标识 | 中国大陆 C 端 | 备案 + 安全评估 + 内容标识 | GB 45438 已强制，硬门槛 |
| NIST AI RMF | 美国 + 国际标杆 | 风险管理 + GenAI Profile | 自愿，政府采购参考 |
| ISO/IEC 42001 | 国际通用 | AI 管理体系认证 | 自愿认证，投标加分 |
| 行业监管 | 金融 / 医疗 / 法律 | 行业特定 SLA + 审计 | 各行业自己定，通常最细 |

关键判断：跨国业务的省心策略是按 EU AI Act（最严）搭工程底座，再叠加当地监管（最直接）的具体要求。因为最严那套的「可追溯 / 可审计 / 可解释」你一旦做到了，其他框架基本是它的子集，提前为最严做反而最省钱。

## 白皮书的 3 大组成 + 8 个段落

不是「为合规重新做工作」，是「把已有产物按合规视角重新组织」。

| 组成 | 段落 | 作用 | 来源 |
| :--- | :--- | :--- | :--- |
| OVERVIEW · 概览 | 1. 系统描述（业务 / 范围）2. 数据来源与契约 3. 模型与算法 | 让审计员懂「做了什么」 | 项目文档 + 契约 |
| EVIDENCE · 证据 | 4. Release manifest 5. 评测报告 + 趋势 6. Trace 抽样 + Bad case | 让审计员看「工程证据」 | Week 11 / 12 / 14 |
| RISK · 风险缓解 | 7. 风险识别与缓解 8. 应急 / 回滚机制 | 让审计员信「出事能控」 | Runbook + Canary，配合 Week 12 / 14 |

这 8 段的来源全是前面几周已经产出的东西。合规白皮书的本质，就是把这些工程产物换一个「监管看得懂」的视角重新排列一遍。治理做扎实了，白皮书是自然产物、一条命令 30 秒生成，而不是外包 $20k+、耗时三周的苦工。

## 合规白皮书自动生成器

从 manifest + 评测 + trace + 血缘汇聚。一条命令，同一个 release 可生成 EU / 中国 / NIST 三份不同视角。生成逻辑要点：

1. **入口只要两个参数**：release_id 和目标框架（如 eu_ai_act），先按 release_id 加载 Week 14 L2 的 manifest。
2. **1-3 段概览**：系统描述读项目蓝图；数据来源从 manifest 的 data 段抽出数据契约；模型信息从 manifest 的 model 段抽出。
3. **4-6 段工程证据**：manifest 原文直接嵌入；评测报告包含 manifest 里的基线值和最近 30 天的指标趋势；trace 抽样取 100 条并强制包含 bad case——让审计员看「真实样本」，比人工写的「案例」可信得多。
4. **7-8 段风险与缓解**：缓解措施写明一键回滚、manifest 里的 canary 策略、以及红线清单（PII = 0、拦截率 ≥ 99%、必须带引用）；事故历史从 Week 12 的 postmortem 库自动汇聚近半年。
5. **整体 digest**：全文按 key 排序序列化后取 sha256，白皮书不可篡改。
6. **framework 参数**：同一个 release 生成 EU + 中国 + NIST 三份不同视角白皮书。
7. **可选公证**：导出时可指定 Sigstore 公证，让白皮书带上数字签名。

## 4 类合规红线

白皮书是「事后给监管看」，红线告警是「事前不让它发生」。

| 红线类别 | 具体指标 | 触发动作 | 法规依据 |
| :--- | :--- | :--- | :--- |
| 数据 · PII 泄露 | PII 出现在输出中 | 立即冻结 + 电话通知合规 | GDPR / 个保法 |
| 数据 · 越权访问 | 低权用户访问高权数据 | 立即冻结 + 安全审计 | 内控 + 行业监管 |
| 推理 · 违规话术 | 生成「保证赚钱」等话术 | 立即拦截 + 模型暂停 | 金融监管 / 反诈 |
| 行为 · 越权动作 | Agent 调未授权工具 | 立即冻结 + Trace 保存 | EU AI Act 透明度 |

踩坑提醒：这 4 类红线绝不能靠人工盯，必须接 Week 12 告警 + Week 14 manifest 的 auto_rollback_on，24/7 自动响应。见过一次 PII 泄露，因为没做自动冻结，从发生到人工发现过了 40 分钟，那 40 分钟里泄了几千条，事后光通知用户、报监管就折腾了一个月。

## 合规红线的工程强制

红线不是「建议」，是 manifest 里可执行的字段。manifest 升级出一个 compliance 段：

| 字段 | 内容 | 说明 |
| :--- | :--- | :--- |
| framework | 适用框架列表（如 eu_ai_act、中国备案 + 标识） | 决定生成哪几份白皮书 |
| risk_class | EU AI Act 风险等级（如 high） | 决定义务强度 |
| red_lines | 每条 = id + metric + threshold + action | 不是建议，是自动强制 |
| audit_chain | generator_digest + signature + previous_release + previous_digest | 链式审计，历史不可篡改 |
| regulatory_reports | 备案号、内容标识合规标志 | 2026 中国 C 端必填 |

三条典型红线：PII 泄露率阈值 0，动作是冻结服务 + 呼叫合规；跨租户访问阈值 0，动作是冻结服务 + 写审计日志；Agent 未授权工具调用阈值 0，动作是冻结 Agent + 归档完整 trace。

要点：

- **action 绑 Week 12 告警 + Week 14 rollback**：触发即执行，不等人。
- **audit_chain**：previous_release + previous_digest 形成链式审计，像区块一样把历史钉死。
- **signature**：把 digest 锚到 Sigstore 签名服务，监管审计时是「数字公证」。
- **内容标识合规**：GB 45438 的内容标识状态入 manifest，2026 中国 C 端必填。

## 监管来查的「30 秒响应」工作流

有工程治理：30 秒导出一份不可篡改白皮书。没有：找文档一周 + 手工拼。

Query（监管 ID / 时间窗）→ Filter（release_id 过滤）→ Export（一键导出白皮书 + 证据）→ Verify（哈希校验 + 签名）→ Deliver（加密传输 + 审计日志）

一条导出命令，给定「哪个版本 + 什么时间」，30 秒汇齐 manifest、评测趋势、trace 抽样（含 bad case）、半年 postmortem、白皮书，全部 ed25519 签名 + RFC3161 时间戳 + Sigstore 锚定，加密传输，连「谁查的」都记进审计。按 EU AI Act 第 12 条，这些要留存 7 年。

监管审查从「项目级紧急任务」降级成「工程系统的日常输出」，这就是治理的最终价值。

## Industry Signals（2026）

合规已从「软约束」变成「硬门槛」：工程治理不是先进做法，是准入资格。

| 来源 | 信号 | 给你的判断 |
| :--- | :--- | :--- |
| EU AI Act | GPAI 执法 2026-08、透明度 2026-08 生效 | 进欧盟必须可追溯 / 可审计，没治理不能上 |
| 中国 GB 45438 | AI 内容标识 2025-09 强制 | C 端服务：备案 + 内容标识是硬门槛 |
| Anthropic RSP / system card | 每个 release 附风险评估 + 卡片 | 业界事实标准，发布必带 |
| NIST GenAI Profile | 把 AI 风险管理做成可操作框架 | 美国政府采购参考，自愿但加分 |

2026 年，AI 合规已经从「要不要做」变成「不做就上不了线」。但别把它当成纯负担：合规恰恰是把前面所有工程治理「变现」的地方——同样一套 manifest + trace + 血缘 + 评测，对内是排障和回滚的工具，对外就是过监管、拿标、投标的资本。治理做扎实的团队，合规是顺水推舟；治理欠账的团队，合规就是那道永远过不去的坎。
