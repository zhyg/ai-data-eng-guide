# 导学 04：监管要一份可追溯的材料，你能当场交出来吗？

## 一句话理解

把前面几周已经产出的发布清单、评测报告、链路追踪记录和血缘账本，按监管看得懂的视角自动汇聚成一份合规材料，同时把几条绝对不能碰的红线写成机器自动强制执行的规则。

## 用生活打比方

继续我们的工厂。外部审核员上门了，要看某一批产品是怎么做出来的。

没建档的工厂这时候开始拼材料：翻邮件找当时的配方是哪版、问老师傅参数调了多少、检验记录找不着就补一张。拼出来的材料自己都不敢保证准。

建了档的工厂另一套流程：调出这批的批号，配套材料、审批签字、检验记录、试行期的观察记录、期间出过什么问题怎么处理的，全都在，当场就能交。这些材料平时本来就在填，只是按审核员关心的顺序重排了一遍。

工厂里还有另一类规矩，跟事后交材料无关：安全项一旦触碰，当场停线，不等谁来审。这两件事都要做，一个是事后能说清，一个是事前不让它发生。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **合规白皮书** | 交给监管或审计方看的一份成套材料，说明这套系统做了什么、用了哪些数据和模型、有哪些工程证据能证明它可控、出事怎么处置。内容全部来自平时已有的工程产物。 |
| **白皮书的三大组成（OVERVIEW / EVIDENCE / RISK）** | 概览部分让审计方看懂做了什么，包括系统描述、数据来源与约定、模型与算法；证据部分给出发布清单、评测报告与趋势、真实调用记录抽样；风险部分说明识别出哪些风险、怎么缓解、出事怎么回退，并附上近期每次故障的复盘记录。 |
| **风险等级（risk_class）** | 按监管框架给这套系统定的风险档位。档位越高，需要履行的义务越多，这个字段直接写进发布清单里。 |
| **合规红线（red_lines）** | 一碰就立刻处置的硬性指标，每条包含编号、看哪个指标、容忍到什么程度、触发后做什么动作。比如输出里出现个人信息就立刻冻结服务并通知合规，自动程序调用了未授权的工具就立刻冻结并归档全部调用记录。 |
| **坏例抽样（bad case）** | 从真实调用记录里抽样时刻意把答错的样本也放进去。给审计方看真实的失败样本，比人工写的漂亮案例可信得多。 |
| **主流合规框架** | 不同市场看不同的框架：面向欧盟市场的 EU AI Act 要求可解释、可追溯、可审计，最严；国内面向个人用户的服务要备案、过安全评估、做内容标识；NIST AI RMF 和 ISO/IEC 42001 属于自愿采纳，用于政府采购参考或认证加分。 |
| **链式审计（audit_chain）** | 每一次发布都在自己的记录里写上前一次发布是哪个、前一次的摘要是什么，一环扣一环。中间任何一次记录被改过，链就对不上，历史因此改不动。 |
| **内容标识** | 面向个人用户的服务，生成的内容必须标明它由 AI 生成。这项在国内已经是强制要求，合规状态要作为一个字段写进发布清单。 |

## 避坑提醒

- **以为合规是上线前再补一份文档**：临时补的话要外部找人照模板写，费用高、来回好几周，还经常因为拿不出工程证据而反复返工。发布清单、评测、追踪记录、血缘平时就在产生，材料应该由工具自动汇聚，随时能出。
- **以为照着前两年的监管资料准备就行**：监管口径变化很快。有的国家曾被广泛引用的那份行政令已经废除，有的地区高风险义务被推迟但透明度义务照常生效，国内则新增了生成内容必须标识的强制要求。拿一份已经失效的依据去跟法务对齐，会直接返工。
- **以为白皮书写好了就算合规做完了**：白皮书是事后能说清，管不住事中。个人信息泄露、越权访问、违规话术、越权动作这几类要在发生的当时就被拦住，靠事后一份材料补不回来。
- **以为红线可以靠人盯着**：人盯着的话，从发生到有人发现可能已经过去很久，这段时间里损失一直在扩大。红线要写成发布清单里可执行的字段，接上告警和自动回退，全天候由机器掐断。
- **以为跨国业务要为每个监管框架各做一套**：按最严的那套搭工程底座，其他框架的要求基本是它的子集，再叠加当地最直接的具体要求就够了。为最严的准备反而最省事。

## 一句话总结

> **合规材料由工具从发布清单、评测、调用记录和复盘记录自动汇聚，按版本和时间窗随时一键导出，并算出整体摘要与前后勾稽的链条；红线则写成清单里的可执行字段，触发即自动处置。**
