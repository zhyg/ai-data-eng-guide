# 导学 03：技能包越攒越多，AI 的脑子会不会被塞爆？

## 一句话理解

渐进式加载是把技能包分三步按需读取：平时只记住每个包的名字和简介，用到哪个才展开它的详细步骤，真要干活时才去调脚本、翻资料，这样几百个技能包也挤不爆 AI 的工作空间。

## 用生活打比方

继续我们的餐厅后厨。后厨不可能一开张就把几百道菜的完整菜谱全铺在操作台上，那样厨师连转身的地方都没有。正确做法是台上先挂一份"菜名加一句话简介"的索引，客人点了哪道菜，才从柜子里翻出那道菜的详细菜谱；真要用到某台设备或某本资料手册时，才去取。

这样一来，菜谱再多，操作台也一直清爽。索引很薄，占地方小，随时挂着；详细菜谱很厚，但只在被点到时才展开。技能加载也是同一个道理。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **渐进式加载（Progressive Disclosure）** | 分阶段按需读取信息，不一次性把所有内容全塞给 AI |
| **三段式加载** | 第一段只读名字和简介（发现），第二段命中了才读完整说明（激活），第三段干活时才调脚本、翻资料（执行） |
| **上下文窗口（context）** | AI 一次能同时看的信息量，是有限的。塞太多没用的东西，真正的对话就装不下了 |
| **发现阶段（Discovery）** | 启动时只加载每个技能的名字和描述，占用很小，常驻在后台 |
| **description 的分量** | 它是发现阶段唯一能被看到的信息，写好写坏直接决定 AI 找不找得到这个技能 |
| **技能路由（Skill Routing）** | AI 从一堆技能里挑出该用哪个的过程。技能少时直接让 AI 挑，技能多时先用向量检索粗筛再挑 |

## 避坑提醒

- **以为一启动就把所有技能全读进来最省事**：技能一多，光简介就能占满工作空间，真正的对话反而没地方放，成本也会大幅上涨。
- **以为 description 随便写句话就行**：写太短或太笼统，AI 要么找不到它，要么什么问题都来触发它。这句描述是整个加载链里信息密度最高的地方。
- **以为技能之间可以随意互相依赖**：一个技能非要先调另一个才能用，会让加载和维护都变复杂。技能应当保持独立。
- **以为技能少时的做法能一直用下去**：技能只有几个时怎么加载都看不出问题，攒到几十上百个还不做按需加载，就一定会撞墙。

## 一句话总结

> **技能系统能不能规模化，取决于加载是不是按需三段式；平时只记名字和简介、用到才展开，是让技能数量长到几百个仍不爆窗口的唯一办法。**
