# 导学 01：为什么老师傅一走，团队的看家本领就跟着没了？

## 一句话理解

Skill 化就是把团队积累的流程、规范、模板、脚本这些手艺，整理成一个标准化的文件夹（一份说明加配套文件），让 AI 助手能自己发现、照着执行，也能在不同工具之间搬来搬去。

## 用生活打比方

这一周我们用"连锁餐厅的招牌菜"来串起所有概念。

一家餐厅最值钱的，往往是招牌菜的做法。可这些做法常常只在老师傅脑子里，或者写在后厨墙上一张发黄的旧纸条上，还有些散在不同分店各自的习惯里。老师傅一离职，招牌菜的味道立刻就变了，新人翻遍资料也拼不回来。

Skill 化要做的，就是把这些做法写成一套标准菜谱包：谁拿到都能照着做出同样的味道，还能原样带到任何一家分店的后厨。团队里那些靠人记、靠口传的经验，第一次有了能交接、能保存的形态。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **技能包（Skill）** | 一个文件夹，装着"某件工作怎么做"的完整说明和配套材料，AI 能发现它并照着执行 |
| **SKILL.md** | 技能包的核心文件，一份 Markdown。上半段是给 AI 看的说明（叫什么、什么时候用），下半段是照着做的步骤 |
| **工艺 / 非代码资产** | 团队里那些不是代码、却很值钱的东西，比如操作流程、检查规范、文档模板、老师傅的经验。它们散在 Wiki、聊天记录、代码注释、口口相传等各个角落，从来没被统一管理过 |
| **三次跃迁** | 行业经历了三次工程化跃迁：先是数据像代码一样版本化（Data as Code），再是 Prompt 像代码一样工程化（Prompt as Code），现在是工艺打包成可移植对象（Skill as Pack）。三层是叠加关系，Skill 站在前两层的肩膀上 |
| **工具（Tool）** | 让 AI 调用的一个具体功能，比如查数据库、发请求。技能包内部可以调用它 |
| **MCP** | 负责把 AI 连到外部系统和数据的接口，管的是"连接"。技能包管的是"连上之后怎么用好" |
| **开放标准（Agent Skills）** | Anthropic 首发、后捐给开放社区的通用格式，多家厂商已跟进。写一次就能在不同 AI 工具里通用，标准已经收敛 |

## 避坑提醒

- **以为把流程写进 Wiki 文档就算沉淀了**：Wiki 最容易过期、没有版本、AI 也读不懂什么时候该用它。技能包是能被 AI 直接发现和执行的包，和一篇文档不是一回事。
- **以为 Skill 是一套复杂的框架或 SDK**：它就是一个文件夹加一份 Markdown，没有专用运行时，简单到能用记事本写出来。
- **以为 Skill 会取代工具、Prompt、工作流**：技能包是把这些东西打包组合起来的容器，它们照样在里面各干各的活。
- **以为团队小就用不上**：可以用几个信号自测，比如关键操作全靠找老师傅、同一份规范在不同项目各写一份、换个 AI 工具又要重新配一遍、新人迟迟上不了手。中几条以上，就是 Skill 化的拐点了。
- **以为可以自己定义一套 Skill 格式**：SKILL.md 已经成为跨厂商的事实标准，自己再造一套就是纯工程债。

## 一句话总结

> **Skill 化是把团队手艺变成可移植、可版本、可治理的标准包，让经验不再随人走，这是团队规模化绕不开的基础设施。**
