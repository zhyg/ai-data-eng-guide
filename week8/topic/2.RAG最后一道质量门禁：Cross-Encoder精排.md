# 2. RAG 最后一道质量门禁：Cross-Encoder 精排

## 核心问题

Hybrid 召回拿到 top-50 候选，但其中只有 3-5 条真正回答 query。直接喂 LLM 等于让模型「在嘈杂里找信号」，token 浪费、注意力分散、幻觉率上升。Reranker 用更慢但更准的 Cross-Encoder 重新打分，精排到 top-3-5，让干净的高质量证据进 LLM。

## 重排是「质量门禁」，不是「锦上添花」

上 Reranker 前后的实测对比：

| 指标 | Hybrid 50 直接喂 LLM | Hybrid 50 + Rerank → 5 | 改善 |
| :--- | :--- | :--- | :--- |
| 每 query token 数 | ~30K（50 chunks x 600） | ~3K（5 chunks x 600） | -90% |
| 每 query API 成本（GPT-4o） | $0.15 | $0.015 | -90% |
| 答案准确率（golden set） | 约 68% | 约 91% | +34% |
| 幻觉率（LLM-judge） | 约 18% | 约 6% | -67% |
| 延迟 P95 | 4.2 秒 | 2.8 秒 | -33% |

真实案例：某 RAG 项目 top-k 调到 50 直接拼 prompt 喂 GPT-4，月账单 $40K，客户还在抱怨「答非所问」。查根因——top-50 里只有 3 条真相关，其他 47 条在干扰 LLM 注意力。

## Bi-Encoder vs Cross-Encoder

这不是同一类模型的两种用法，是结构差异，精度和速度天然权衡。

**Bi-Encoder（用于召回/粗排）**：
- query 和 doc 分别编码为向量，score = cosine(vec_q, vec_d)
- doc 预先 embed 入库，检索时 O(1)，毫秒级查 100 万
- 代价：query 和 doc 不交互，匹配粗糙

**Cross-Encoder（用于精排/重排）**：
- query + doc 拼接后一起进模型，内部 attention 充分交互
- 每对独立计算，O(N) 不能预计算
- 比 Bi-Encoder 慢 100-1000 倍，但精度天花板级

两者的关系：Bi-Encoder 当粗排筛 50 候选，Cross-Encoder 当精排打 5 个最高分，天作之合。

## Two-Stage Retrieval：漏斗式精排

从 100 万 → 50 → 5，每阶段筛掉 95-99%：

```
Index(100万+ chunks) → Hybrid(50候选, Dense+BM25+RRF) → Rerank(5精排, Cross-Encoder) → Filter(阈值过滤, score>0.3) → Generate(干净生成, Citations)
```

score < 0.3 的 chunk 大概率是「召回但无关」，剔除后 LLM 的注意力专注在真正相关的证据上。这套漏斗 + 阈值组合是生产级 RAG 的标准形态。

## 三大门派：Cross-Encoder 不是唯一答案

| 门派 | 代表 | 机制 | 延迟 | 精度 | 适用 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Cross-Encoder | Cohere 3.5 / BGE v2 | query+doc 拼接 encode | 20-100 doc 约 200-500ms | 当下最强 | 生产 RAG 默认 |
| ColBERT (Late-Interaction) | ColBERTv2 / PLAID / Vespa | query/doc 各保留 token 级 vec，MaxSim 打分 | 比 Cross 快 5-10x | 接近 Cross-Encoder | 超大库(1B+)在线 |
| LLM-as-Rerank | GPT-4o / Sonnet / RankGPT | 让 LLM 直接打分排序 | 1-3s/次 | 20 doc 内 SOTA | 高价值 query |

生产推荐组合：Cross-Encoder（Cohere/BGE）+ LLM Rerank Top-5 二次过滤，recall + precision 双高。

## ColBERT Late-Interaction

Bi-Encoder 太弱，Cross-Encoder 太慢，ColBERT 是中间最优解。query/doc 各保留 token 级向量，打分时 query 每个 token 取与 doc 所有 token 的最大相似度再求和（MaxSim）。doc-vec 可预存，在线只算 query，比 Cross 快 5-10x，精度接近 Cross-Encoder。

## Multi-Hop Retrieval

单轮检索打不动的真实问题（如「X 公司 CEO 的母校在哪」）必须 hop 2-3 次。流程：检索 + Rerank → LLM 判断证据是否够答 → 不够则生成 sub-query 再次检索 → 迭代直到充分或达到上限。

实现三派：Agentic RAG（LangGraph，2026 默认）、Graph RAG（Neo4j 图遍历）、Iterative RAG（显式 N 轮）。代价是延迟 5-10x、token 3-5x，仅复杂 query 走。

## 五个常见反模式

| 反模式 | 具体表现 | 后果 | 正确做法 |
| :--- | :--- | :--- | :--- |
| 不上 reranker | top-50 直接喂 LLM | token 炸/准确率塌 | 强制二阶 retrieval |
| 用 LLM 做 reranker | GPT-4o 当 reranker | 贵 100 倍/慢 10 倍 | 用专门 Cross-Encoder |
| top-N 过大 | rerank 后还留 20+ | LLM 注意力分散 | top-N = 3-5 |
| 没用阈值过滤 | score 0.1 也照单全收 | 低分干扰 LLM | score < 0.3 剔除 |
| 不存 rerank_score | 只用排序不存分数 | 前端无法展示置信 | rerank_score 必入 evidence |
