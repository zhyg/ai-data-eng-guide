# 导学 04：改一句 Prompt 为什么能搞垮整个系统？

## 一句话理解

Prompt 是控制 AI 行为的核心指令，必须像代码一样做版本管理、Review、测试和灰度发布，不能随便改了就上线。

## 用生活打比方

继续我们的急诊室。处方单的格式搞定了，但还有一个问题：医院的诊疗指南（相当于 Prompt）谁都能改吗？

如果某个医生周五下班前随手改了一条用药指南，没通知其他人，也没做任何复核。周六一位护士按新指南给药，患者出了不良反应，排查了半天才发现是指南被改过了。问题不在于这位医生粗心，而在于医院没有把诊疗指南当正式文件管理：谁改的、改了哪里、改之前效果怎样、改之后有没有验证过，全都不知道。

Prompt 管理和诊疗指南管理是一回事。Prompt 决定了 AI 怎么回答问题，改一个字段都可能让答案质量变化。它需要有版本号、有审核流程、有回归测试、有灰度发布，才能安全上线。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **Prompt 版本化（Versioned）** | 用 Git 管理 Prompt 文件，每次修改有版本号，有人 Review，能随时查看历史或回退到某个版本 |
| **Prompt 模板化（Templated）** | 用模板引擎把 Prompt 里的变量和固定部分分开。业务数据从外部注入，Prompt 本身只写指令逻辑，方便维护 |
| **Golden Set（黄金测试集）** | 一批真实的测试样本，每次改 Prompt 都跑一遍，看核心指标有没有下降。相当于 Prompt 的回归测试 |
| **LLM-as-Judge（AI 评测 AI）** | 用一个更强的 AI 模型来评判另一个 AI 的答案是否正确。把答案拆成一条条断言，逐条判断是否有证据支持 |
| **Bad Case 库** | 用户反馈"答错了"的案例集合，按原因分类（没检索到、排序错了、AI 编的、知识库里没有）。这些真实的错误案例比测试数据更有价值 |
| **漂移监测（Drift Detection）** | 上线后持续监控 AI 答案质量的变化趋势。即使什么都没改，数据更新、模型微调都可能让效果慢慢变差，必须及时发现 |

## 避坑提醒

- **以为 Prompt 就是代码里的一个字符串**：Prompt 硬编码在 .py 文件里，没版本、没 Review、没测试。出了问题不知道改过什么，也回退不了。Prompt 必须独立成文件，用 Git 管理。
- **以为改 Prompt 不需要测试**：改一个字段可能让部分请求的质量下降，上线前看不出来，几天后 Bad Case 集中爆发。每次改动都必须跑 Golden Set 回归测试。
- **以为 Prompt 新版本可以直接全量上线**：直接全切新版，一旦出问题就是全量用户受影响。正确做法是先灰度一小部分流量，观察指标稳定后再逐步扩大。
- **以为上线后效果会一直稳定**：数据在更新，模型版本在迭代，Prompt 效果一定会慢慢漂移。不做持续监测，三个月内必然出问题。

## 一句话总结

> **Prompt 是软件资产，版本化、测试化、灰度发布、漂移监测四件事少做一件，上线后都是隐患。**
