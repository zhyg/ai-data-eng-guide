# 导学 02：一堆候选结果里大部分是噪音，怎么筛？

## 一句话理解

混合检索拿到的候选结果大部分是噪音，用 Cross-Encoder 重新打分，只留下少量最相关的结果，能同时降低成本、提高准确率、减少幻觉。

## 用生活打比方

继续我们的急诊室。上一步护士通过多种检查手段筛出了一批疑似相关的病历档案，但里面大部分和当前病人的情况对不上，真正有用的只有几份。

如果把一大摞全堆到医生桌上让医生逐一翻看，医生注意力分散，很可能忽略关键信息，还浪费大量时间。正确的做法是：安排一位资深专家先快速过一遍，把最相关的几份挑出来，再交给主治医生仔细看。

Reranker 就是这位资深专家。它比初筛慢，但判断更准，能把真正相关的证据挑出来，让后面的 AI 只看最干净的信息。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **精排（Rerank）** | 对粗排结果重新打分排序的过程。粗排追求"别漏掉"，精排追求"排得准"，两阶段配合是生产标配 |
| **Bi-Encoder** | 把查询和文档分别转成向量再算相似度，速度很快，能在海量数据中即时检索，但匹配比较粗糙，适合粗排阶段 |
| **Cross-Encoder** | 把查询和文档拼在一起送进模型，让模型充分理解两者的关系再打分。速度比 Bi-Encoder 慢很多，但精度高很多，适合精排阶段 |
| **ColBERT（Late Interaction）** | 介于 Bi-Encoder 和 Cross-Encoder 之间的方案：文档部分可以预计算存好，在线只算查询部分，速度比 Cross-Encoder 快不少，精度接近 |
| **阈值过滤** | 精排打分后，低于某个分数的结果直接丢弃。分数太低说明"虽然排进来了但其实不相关"，留着只会干扰 AI |
| **多跳检索（Multi-Hop Retrieval）** | 一轮检索找不全答案时，AI 判断还缺什么信息，生成新的子问题再检索一轮，迭代几次拼齐完整证据 |

## 避坑提醒

- **以为粗排结果直接给 AI 就行**：候选结果里大部分是噪音，在消耗 token、分散 AI 注意力、推高幻觉率。加 Reranker 后准确率会明显提升，幻觉率也会大幅下降。
- **以为用大语言模型当 Reranker 效果更好**：用大语言模型当 Reranker 比专用 Cross-Encoder 贵得多、慢得多，而且精度并没有明显优势。专用工具做专用的事。
- **以为精排后多留几条更保险**：精排后留太多条和不精排差别不大，AI 的注意力依然会分散。只保留少量最相关的结果效果最好。
- **以为精排分数只用来排序就够了**：精排分数应该存到结果里。前端可以用分数做置信度展示，后端可以用分数做质量分析，丢掉分数等于丢掉了很有价值的信号。

## 一句话总结

> **精排不是锦上添花，而是生产 RAG 的质量门禁：候选结果经过精排大幅缩减，token 成本和幻觉率同时下降，准确率明显提升。**
