# 导学 04：取回来的节点和边，为什么不能直接丢给大模型？

## 一句话理解

图增强生成要先把取回的节点和边翻译成大模型读得懂的文本，再按检索模式套用对应的提示词模板，最后把文档原文和图结构一起作为证据返回。

## 用生活打比方

继续我们的资料室。该取的卡片和路径都取回来了，接下来要汇报给领导。把一叠卡片连着线头原样端到领导桌上，领导也能猜个大概，但往往走偏。领导看不懂是因为卡片和线属于贴墙用的工具，需要专门翻译成汇报语言。

三种取法对应三种译法。顺着线走出来的路径，写成一串句子，一句一步；从一张卡片向外扩展取回的一小片墙，画成表格，每行一条关系；按区块取回的概述，本来就是纸条上的文字，照抄即可。翻译完还有一件事不能忘：每一句结论后面都要注明出自哪份文件哪一段，线索和凭据两样都得带上。

最后，三种取法要配三份不同的汇报口径。「基于这一小片墙里的对象说事」和「跨几个区块总结共同点」是两种活，用同一份口径去讲，归纳会变成罗列，聚焦会变得发散。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **序列化（serialize）** | 把图检索取回的节点和边转换成文本的过程。大模型是在文本上训练出来的，喂它一句「A 收购了 B」它立刻懂，喂它一段描述同一件事的结构化数据它反而读不准。 |
| **三种序列化策略** | 路径转文本，把每一步关系写成一句「谁 做什么 谁」；子图转表格，输出一张表，每行是一条关系；社区转摘要，直接用预先算好的那段概述。分别配合路径遍历、子图扩展、全局检索三种检索模式。 |
| **prompt 模板** | 每种检索模式各写一份的提示词。聚焦类要求只用给定子图里的对象作答；归纳类要求跨组总结规律、指出共性和异常；路径类要求把关系链清楚地一步步列出来，每一步都有给定路径支撑。 |
| **图证据（GraphEvidence）** | 图增强新增的证据类型，说明这次用的是子图、路径还是社区摘要，以及锚点是谁、路径写出来是什么。它里面同样保留来源知识块，所以图证据也能反查原文。 |
| **检索模式（retrieval_mode）** | 响应里显式记录这一次走的是哪条检索路：纯向量、子图扩展、全局检索、路径遍历还是混合。 |

## 避坑提醒

- **以为图数据丢进提示词就是能直接用**：节点和边的结构化写法对大模型来说不好读，它会给出似是而非的解读。同一片子图，翻译成表格再喂，准确率比直接丢结构化数据高出一截。这一步的翻译质量直接决定生成质量。
- **以为提示词模板就是一套能通用**：聚焦、归纳、路径三类任务的目标完全不同。用同一份模板，该归纳的变成了逐条罗列，该聚焦的又答得漫无边际，前面检索取得再准也白搭。
- **以为有了图证据就是不用给原文了**：图关系看起来很有说服力，容易让人只顾着展示结构，把原文引用丢掉。一旦被追问依据，图只能给出线索，给不出可核对的凭据。合规和信任上，凭据的地位永远高于线索。
- **以为图增强就是要重写整条生成链路**：整条流水线里真正新增的只有序列化和图证据这两块，题型路由、受约束生成用的还是前几周那一套，代码绝大部分原样复用。
- **以为检索模式就是不用记的**：不把检索模式记进响应，图和向量的结果混在一起，评测时就永远算不清图到底在哪类问题上赢了、在哪类其实是白花钱。

## 一句话总结

> **序列化和提示词模板这一层没有高深算法，全是手艺，但前面建的图、调的检索能不能变成一个好答案就取决于它；同时图证据和原文证据必须一起返回，还要显式记下这次用的检索模式。**
