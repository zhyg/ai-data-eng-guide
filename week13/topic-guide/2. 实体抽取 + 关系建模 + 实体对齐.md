# 导学 02：同一家公司在图里有五个名字，这张图还能用吗？

## 一句话理解

图构建分三步：先定好允许出现哪些实体类型和关系类型，再按这套规范从知识块里抽出实体和关系，最后把同一个对象的多种写法合并成一个节点。

## 用生活打比方

继续我们的资料室。领导批了预算，可以做那面关系图墙了。

最省事的做法是把一叠文件分给几个人，说「你们看着抄，见到重要的东西就写张卡片贴上去」。一周后回来看墙，会发现问题：有人写「产品」，有人写「产品线」，有人写「商品」，指的其实是一回事；连线上有人写「负责」，有人写「归属」，有人干脆写「相关」；同一家公司在墙上贴了五张卡片，写法各不相同，本该汇到一处的线全被切碎了。这面墙没法看，更没法顺着线找东西。

正确的做法反过来：先印一批标准卡片，规定卡片只有几种，比如客户卡、工单卡、产品卡、故障卡，每种卡片上填哪几栏也写清楚；连线也只允许几种，每种写成固定的动词。规范定下来，再让人照着抄。抄的时候还有两条硬规矩：每张卡片和每条线都得注明是从哪份文件哪一段抄来的；拿不准的宁可空着别写。

抄完还有最后一道活，也是最费工的一道：把墙上重复的卡片合并。「艾克美公司」「艾克美」「Acme Inc」大概是同一家，但也可能不是。先查预先整理好的别名表，查不到就比字面写法，还拿不准就交给人判断。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **图规范（Graph Schema）** | 一份规定图长什么样的配置：允许出现哪些实体类型、哪些关系类型、每种类型上必须填哪些字段。它带版本号，改动要走版本管理。比如规定只能出现人员、公司、产品等对象类型。 |
| **规范先行（Schema-first）** | 先把规范定完再开始抽取的做法。反过来先抽再补规范，抽出来的东西类型混乱，后面所有算法都会被干扰。比如先规定好只提取公司和产品，然后再让系统去文档里找。 |
| **节点类型与关系类型（Node Types / Edge Types）** | 节点类型指图里允许出现的对象种类，比如人、组织、产品、问题；关系类型指允许出现的联系种类，写成标准化的动词，比如「提交人是」「影响了」。含糊的写法（比如「有关联」）要禁掉，否则沿着这种边推不出任何结论。 |
| **别名（aliases）** | 节点上专门存这个对象其他写法的字段。同一家公司的简称、全称、外文名、译名都记在这里，是后面合并重复节点的基础。 |
| **原文片段（evidence_text）** | 抽出一条关系时，同时记下支持这条关系的那句原文。有了它，后面才能人工复核，出错也能追到源头。 |
| **置信度（confidence）** | 一条关系有多可靠的打分。抽取时记下来，检索时用它区分可靠关系和勉强抽出来的关系。 |
| **实体对齐（Entity Resolution）** | 判断两个写法不同的实体是不是同一个对象，是则合并成一个图里的条目。不做这一步，同一个对象在图里变成几个互不相连的图里的条目，关系全被切碎。比如把文档里出现的某家公司的全称和简称合并为同一个。 |
| **时序知识图（Temporal Knowledge Graph）** | 每条关系上都带「这个事实从什么时候到什么时候成立」的图。公司改名、并购、人员变动这类变化在普通图里存不下，只能覆盖掉旧事实；带时间的图能把新旧两个名字都留着，还能回答改名前叫什么。 |

## 避坑提醒

- **以为图构建就是让大模型抽一遍**：不定规范直接抽，出来的实体类型多得离谱、关系动词五花八门、颗粒度粗细不一。基于这种图做的社区归纳、路径遍历、子图扩展全都会被噪声击穿，图算法再好也救不回来。
- **以为实体对齐就是字符串去重**：去重只能处理写法接近的情况。缩写和外文译名字面上毫不相似，同名不同类（一个产品名恰好和一家公司同名）字面上又完全一样，这两类都得靠上下文和额外判断。
- **以为实体对齐的最佳方案就是全交给大模型判断**：图一大，需要两两比对的实体数量涨得很快，全交给大模型判断，光对齐的开销就能超过抽取本身。要分层：先查别名表，再比字面写法，再比语义相近程度，只把真正判断不清的少数情况交给大模型。
- **以为信息抽取的原则就是宁可多抽也不要漏抽**：错抽的实体和关系一旦进图，会污染所有沿着它推理的结果，而且很难发现。提示词里要明确写「拿不准就跳过」，漏抽的损失比错抽小得多。
- **以为实体的名字就是固定不变的**：一家公司可能改名，一个产品可能并入另一条产品线。领域里的实体会随时间变，就别再用普通图硬抗对齐，直接上带时间的图。

## 一句话总结

> **图建错了下游全都救不回来，所以规范要先定死、抽取要带原文和置信度、对齐要分层做，把大模型只用在真正判断不清的少数情况上。**
