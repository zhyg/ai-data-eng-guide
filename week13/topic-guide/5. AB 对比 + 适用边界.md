# 导学 05：花了这么大力气建的图，怎么证明它有用？

## 一句话理解

A/B 对比要把评测集按题型分成几类，同一批问题让向量和图两条路并行跑，分类统计每类的答案质量和开销，用数据决定图该在哪类问题上上场。

## 用生活打比方

继续我们的资料室。关系图墙做出来半年了，领导来问：这面墙到底值不值那些工时？

只看一个总分回答不了这个问题。详细统计各分类后会发现，占比最大的那批简单提问，用墙反而比翻手册还差一点；占比不大的归纳类提问，用墙好得多；一平均，总分看着微涨。正确的做法是分类记账：先把提问分成四类（聚焦、归纳、绕弯、查事实），同一批提问同时交给两组人，一组翻手册、一组用墙，每一类分别统计答案质量和工时。结论会很清楚：归纳类和绕弯类才上墙，其余翻手册。判断这一步很便宜，扫一眼问题就能分。

还有一件事得从第一天就做：墙上有多少卡片、多少条线、划了几个区块、纸条是哪一版，都要登记在册，和文件目录的版本对齐。不登记的墙，半年后就是没人敢碰的一堆卡片。

## 关键概念

| 概念 | 大白话解释 |
| :--- | :--- |
| **按题型分层（by_category）** | 评测统计时按题目类别分组算，避免把所有题目混成一个平均分，比如把局部聚焦题和多跳推理题分开统计。混着算，某一类的大幅提升会被另一类的小幅下降摊平，看上去只是微涨。 |
| **四类题型** | 聚焦类（focal）问某个具体对象的情况；归纳类（global）问跨多份文档的共性和分布；多跳类（multihop）问需要绕几道关系才能到的答案；事实类（factual）问一个明确的具体信息。 |
| **多模型 Judge** | 用两个不同厂商的大模型互相评判同一批答案。单一裁判有自己的偏好，容易系统性地偏向某种回答风格。 |
| **影子流量** | 把一小部分真实线上提问复制一份，交给图这条路跑一遍，只用于评测、不返回给用户，比如把一部分用户的真实提问镜像过来跑测试。自己造的评测题和真实用户的问法差别很大，只有影子流量能反映真实的题型分布。 |
| **成本倍数（cost_overhead）** | 图这条路比向量这条路多花的开销比例，比如对比一下图检索比向量检索多花了多少算力。它是决策的关键指标，答案质量提升一点点但开销翻好几倍，这笔账不一定划得来。 |
| **题型分类器（classifier）** | 每个提问进来先判断它属于哪一类、该走哪条检索路的小模块。用最便宜的小模型就够，是整条链路里开销最低的一环。判断置信度低的时候直接降级走向量，避免把简单问题误推到贵的图链路上。 |
| **发布清单里的图版本段（graph_release）** | 发布清单里专门记录图的那一段：schema 版本、抽取用的模型、实体数、关系数、社区数、摘要版本、上次全量重建时间，还有分类器的提示词版本和置信度阈值。这些元素绑在一起发布，出问题能整体回滚。 |

## 避坑提醒

- **以为总体指标涨了就是该上线**：总体分是各类题型的加权平均，最容易掩盖真相。占比大的简单题型稍微变差、占比小的归纳题型大幅变好，混在一起看就是微涨。该看的是主场题型提升了多少，乘以它的占比，够不够抵掉多出来的开销。
- **以为自己造的评测题就是真实提问的代表**：手工写出来的题目往往比真实提问更规整、更贴合你以为的场景。拿它下结论，很容易出现实验室数据好看、上线之后拉胯的情况。
- **以为一个裁判模型的打分就是结论**：单个裁判模型的偏好会系统性地影响打分，让某一条路无缘无故占便宜。换两个不同厂商的模型互判，偏差才能被抵掉一部分。
- **以为分类器要用最强的模型**：分类只是从几个固定类别里挑一个，用最便宜的小模型加上几条确定性规则就够，输出还能用结构化格式焊死取值范围。把预算花在这一环上是浪费。
- **以为评测和可观测就是可以上线后再补的**：评测、追踪、告警、版本治理、反例沉淀这几样，加在已经跑起来的服务上比从零建难得多。上线时把图当外挂挂着，过一段时间就成了没人敢碰的黑盒，最后只能整个下线重来。

## 一句话总结

> **图只在归纳类和多跳类问题上回得来本，所以要靠一个便宜的分类器把每个提问送到合适的那条路上，并且从上线第一天就把评测、可观测、告警、版本治理、反例沉淀一起接上。**
